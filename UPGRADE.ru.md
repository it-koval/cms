# Обновление ITK CMS

## Как обновить сайт

Делайте шаги по порядку, сначала на копии сайта:

1. Прочитайте [CHANGELOG.ru.md](CHANGELOG.ru.md) за все версии между вашей и целевой, а также заметки к версиям в конце этого файла.
2. Сделайте резервную копию базы данных.
3. Обновите пакет: `composer update itk/cms`. В комплекте Docker выполните `docker compose exec php composer update itk/cms`.
4. Выполните миграции: `bin/console doctrine:migrations:migrate`. Миграции бандла (`Itk\Cms\Migrations`) выполняются вместе с миграциями сайта, в порядке дат в именах их классов.
5. Опубликуйте собранную админку командой `bin/console assets:install`. Symfony Flex делает это при `composer install` и `composer update`. Затем очистите кэш командой `bin/console cache:clear`.
6. Перезапустите воркеры очереди командой `bin/console messenger:stop-workers` или перезапуском сервиса. Работающий воркер держит старый код.
7. Проверьте сайт: выполните `bin/console itk:doctor` и `bin/console itk:schema:lint`, затем откройте админку и несколько страниц.

Если заметки к версии просят изменить конфигурационный файл сайта (например, `security.yaml`), сделайте это до шага 7.

## Версии

ITK CMS следует [семантическому версионированию](https://semver.org/lang/ru/spec/v2.0.0.html):

- Патч-релиз (0.1.1) содержит только исправления.
- Минорный релиз (0.2.0) добавляет возможности. Начиная с 1.0.0 он не ломает публичный API.
- Мажорный релиз (2.0.0) может ломать публичный API.

До версии 1.0.0 минорный релиз может ломать публичный API. Каждое такое изменение указано в [CHANGELOG.ru.md](CHANGELOG.ru.md) и в заметках к версиям ниже. Патч-релиз его никогда не ломает. Чтобы получать исправления без сюрпризов, закрепите в сайте минорную версию: `"itk/cms": "~0.2.0"`.

Изменения базы данных поставляются миграциями бандла. Бандл не меняет собственные таблицы сайта.

#### Другие изменения

- Поле **«Фотографии»** теперь добавляет из админки объекты `{src, alt}`, в том числе при пустом `alt`. Старые строки с URL остаются без изменений: в одном поле могут быть и строки, и объекты. Обновите шаблоны сайта до добавления новых фотографий редакторами; для каждого значения предусмотрите прежний формат:

  ```twig
  {% for p in photos %}
      <img src="{{ p.src ?? p }}" alt="{{ p.alt ?? '' }}">
  {% endfor %}
  ```

- `GET /admin/api/requests` и `GET /admin/api/media` вместо массивов возвращают `{ items, total, page, perPage, nextCursor, previousCursor }`. По умолчанию первая страница содержит до 50 строк. Максимум 100 строк на страницу. Чтобы перейти на соседнюю страницу при изменениях списка, передайте полученный курсор в `cursor` с теми же фильтрами. Инструменты MCP `requests_list` и `media_search` также принимают курсор и поддерживают `offset` и `limit`.
- В `GET /admin/api/dashboard` массив `newRequests` содержит восемь последних новых заявок. Полное число даёт `newRequestCount`, полный список выдаётся постранично через список заявок с `status=new`.

Встроенную inline-инициализацию аналитики заменяет один версионированный внешний загрузчик с `defer` и атрибутами `data-*`. Опубликуйте новые ассеты бандла через `bin/console assets:install` и разрешите в CSP сайта фактический источник ассетов и нужные источники провайдеров. [Руководство по аналитике](packages/cms/README.ru.md#аналитика-и-коды-подтверждения) описывает `script-src`, `connect-src`, `img-src` и условие для `frame-src` Вебвизора.

Даже в `auto` функции `ym`, `gtag` и массив `dataLayer` могут быть не определены во время разбора HTML или выполнения более раннего скрипта сайта с `defer`. Перенесите ранние вызовы в обработчики `DOMContentLoaded` в режиме `auto` либо дождитесь нужного счётчика через `window.itkAnalytics?.started` и `itk-analytics:started`. Событие в `auto` может произойти во время выполнения загрузчика, до следующих скриптов сайта. Перед подпиской проверьте ключ счётчика (`metrika` или `ga`), а последующие события фильтруйте по `detail.counters`. В руководстве есть пример внешнего JavaScript. Можно также определить заглушки очередей во внешнем скрипте, который выполняется раньше загрузчика и ранних вызовов. Загрузчик сохраняет существующие очереди `ym`, `dataLayer` и `gtag`.

Для CSP с nonce и `strict-dynamic` сайт должен генерировать новый nonce для каждого ответа, до рендеринга задавать доверенный атрибут запроса Symfony `csp_nonce` и использовать тот же nonce в заголовке CSP и тегах скриптов сайта. CMS берёт nonce для загрузчика из этого серверного атрибута. Запросы с nonce обходят HTML-кеш страниц CMS и условную обработку ETag. Аналогично настройте кеши ответов сайта и внешних прокси. Для `connect-src`, `img-src` и нужных `frame-src` по-прежнему нужны источники провайдеров. Руководство показывает подключение в Twig, включая явный аргумент `itk_stylesheets({nonce: ...})`.

По умолчанию `itk_cms.analytics.start` равен `auto`, который запускает настроенные счётчики и сохраняет пиксель `<noscript>` Метрики. Для запуска по решению посетителя в баннере сайта задайте `analytics.start: manual` внутри `itk_cms` в конфигурации сайта. В админке режим не переключается. Перед переходом уберите из сайта прямые скрипты счётчиков, пиксели, триггеры менеджера тегов и ссылки `preconnect` или `dns-prefetch` для аналитики. В `manual` бандл не выводит пиксель и не делает запросов или предварительных соединений с провайдерами до вызова API. Метатеги подтверждения выводятся в обоих режимах, в том числе без счётчиков.

После выполнения загрузчика бандла вызовите `window.itkAnalytics.start()` для всех настроенных счётчиков или `window.itkAnalytics.start(['ga'])` только для GA. Допустимые ключи — `metrika` и `ga`. Новые запуски отправляют на `document` событие `itk-analytics:started`, всплывающее до `window`, с ключами новых счётчиков в `detail.counters`. Повтор без нового счётчика не создаёт событие. Руководство содержит внешний скрипт согласия, который дожидается загрузчика. Подключите его с `defer` либо после `</head>` и разметки баннера, чтобы тег загрузчика и кнопка уже были в DOM. Его URL учитывает базовый путь сайта и работает в подкаталоге. Сайт хранит согласие и после его отзыва перезагружает страницу без вызова `start()`. CMS не останавливает уже работающие счётчики.

- Добавьте `->forAuthors()` к своим шаблонам статей, которые должен редактировать Автор. У встроенного `blog_article` признак уже задан.
- Для писем восстановления и приглашений задайте полный адрес в `itk_cms.public_url`. Миграция гасит открытые ссылки. Удалите прежние задания и готовые письма для паролей из рабочих очередей и очереди ошибок, затем запросите новые ссылки.
- Для сохранённых учётных данных SMTP включите STARTTLS или SSL/TLS. Старый пароль с отключённым шифрованием сохраняется. Доставка возобновится после исправления настроек. Для аутентификации с паролем в `MAILER_DSN` укажите `smtps://` или `smtp://` с `require_tls=1`. «Состояние сайта» и `itk:doctor` предупреждают о необязательном TLS.
- Выполните миграции бандла до использования сохранённых настроек SMTP: они теперь хранятся в общем внутреннем ключе `itk:mail` независимо от поля сайта `mail`. Миграция `20261124110100` переносит только известный объект SMTP. Если прежняя миграция пространства имён перенесла в `itk:mail` другое значение, оно возвращается в `mail`, когда тот отсутствует. При наличии обоих ключей сохраняются оба значения; проверьте конфликт до использования сохранённых настроек SMTP. Языковые значения сайта не меняются.
- У публичной формы по умолчанию предел тела 256 КиБ. У поля без `max()` предел 1000 символов. Задайте нужные пределы полей и согласуйте `itk_cms.requests.max_body` с PHP и прокси. Клиент формы должен показывать ошибки полей и обрабатывать HTTP 413.
- Клиент API повторной отправки читает результат каждого выбранного канала в `outcomes`. HTTP 202 означает ожидающее задание выбранного канала. `queuedChannels` показывает очередь и при повторном открытии заявки. Штатный транспорт `async` повторяет доставку через 60, 120 и 240 секунд. Настройки транспорта сайта имеют приоритет.
- Внутренние методы `MediaService::usage()` и `present()` с включённым использованием теперь требуют явного `Viewer`. Добавьте `PublicFieldInterface` кастомным полям, доступным для индексации, и реализуйте `isPublic()`.
- Для автоматического создания администратора в Docker-ките подключите секрет `itk_admin_password` к `php` или запустите установку интерактивно. Уберите прежнюю переменную `ADMIN_PASSWORD`. Скопируйте `docker/chrome-seccomp.json` и подключите его к `php` и `worker` для критического CSS. Скопируйте обновлённый конфиг nginx, чтобы предел формы срабатывал до разбора PHP.
- При создании администратора установщиком используйте пароль длиной от 10 до 200 символов. Те же пределы действуют для `--password-file`.
- Действия коллекций требуют входа и разрешения. Блокировка пользователя закрывает доступ при следующем запросе. Управляющие символы делают URL ссылки или изображения в редакторе недопустимым. MCP `request_get` возвращает до 6000 символов значения формы.
- Если база знаний уже проиндексирована, выполните `itk:knowledge-base:sync --now` перед открытием поиска. Команда обновляет документы, чьи заголовки раньше брались из непубличных полей.
- Запустите миграции бандла до запуска воркеров. Они переносят внутренние настройки в пространство `itk:`, приводят имя колонки даты создания страницы к `created_at` и оставляют старейшее уведомление на каждый ключ. Отметки о прочтении дублей переходят в оставленную запись.
- Миграция переносит настройку, если сохранённый JSON имеет ожидаемый внутренний тип. Это правило действует и для маршрутов и переключателей доставки. Интеграции админки могут читать и менять их через `/admin/api/settings?scope=notifications` с прежними именами полей.
- При откате служебная настройка сохраняет ключ `itk:`, если её прежний ключ занят полем сайта. Чтобы вернуть старую конфигурацию, сначала перенесите поле сайта и его значение на свободный ключ. Затем верните служебное значение под прежний ключ.
- При откате миграции даты создания страницы сохраняется `created_at`. Такое же имя используется в исходной схеме 0.2.2.
- Переименуйте поля коллекций с ключами метаданных. Список есть в `Collection::RESERVED_KEYS`. До первого сохранения singleton возвращает черновик с начальными значениями. Явное сохранение создаёт запись и историю.
- Если коллекция использовала `locales` или `position` как бизнес-поле, переименуйте его в схеме, сохранённых черновиках и опубликованных значениях. В генераторе из таблицы зарезервированную колонку источника можно переименовать через `--map`.
- Запустите `itk:schema:lint` для проверки ссылок `h1()` и ключей полей. Отмечайте первый экран через `firstScreen()` при любой подписи группы. Для канбана используйте отдельное поле, например `stage`.
- Сервисы записи одинаково проверяют варианты, ограничения и форматы дат. Проверьте данные импорта и собственные сервисы записи. Свои поля могут добавить проверку через `ValueValidatingFieldInterface`.
- `regex()` также проверяет непустые значения при записи через админку, PHP и импорт. Исправьте сохранённые значения, которые не подходят под шаблон, перед публикацией.
- Публичные формы отклоняют непустые значения вне списка вариантов. Пустое необязательное поле допустимо.
- Публичные формы отклоняют неверные форматы даты и времени.
- Значение формы длиннее заданного предела даёт ошибку валидации.
- Поля дат без явно заданного начального значения теперь пустые. Перед публикацией старых черновиков коллекций замените текстовые заглушки вроде «Новый пункт» реальными датами. Для даты используйте `ГГГГ-ММ-ДД`, для местной даты и времени `ГГГГ-ММ-ДДTчч:мм`.
- Адрес страницы должен быть локальным путём до 255 символов. Параметры запроса, фрагменты, обратная косая черта и управляющие символы недопустимы. Пробелы, Unicode и двойной слеш внутри пути допустимы. В публичных ссылках пробелы и Unicode кодируются.
- Размещайте переопределения Twig в `templates/bundles/ItkCmsBundle/`. Для наследования оригинального шаблона используйте `@!ItkCms/…`.
- Проверьте `framework.default_locale` для консоли и Messenger. `itk_cms.admin_locale` задаёт язык интерфейса CMS. Адресное письмо использует язык получателя.
- Файлы бандла берут базовый путь и адрес CDN из Symfony Asset, сохраняя собственные имена. Версия и JSON-манифест сайта действуют для его ассетов. Если админка собирается на сайте, пересоберите её ассеты. При переданном CSP nonce полный файл стилей загружается обычной ссылкой.
- `domain` принимает хост или адрес HTTP(S) без пути, параметров и фрагмента. Карта сайта использует валидный `itk_cms.public_url`, затем `domain`. Одноязычная карта с одной настройкой `domain` сохраняет написание версии 0.2.2. IndexNow и Вебмастер используют нормализованный адрес.
- Переадресация по пути имеет приоритет. Правила с параметрами сравнивают их после нормализации и учитывают регистр. Для своего периода заявок задавайте даты в формате `ГГГГ-ММ-ДД`.
- Создание токена MCP отклоняет неизвестное право.
- При доставке из очереди и повторной отправке слушатели `RequestDelivery` вызываются после фиксации итога. Для изменения заявки загрузите её по ID через свой менеджер сущностей и явно сохраните. Исключения слушателей записываются в журнал и не повторяют отправку.
- Сохраните заявку перед доставкой. Если приложение уже открыло транзакцию, CMS фиксирует итог доставки и уведомление в админке независимо от неё.
- `GET /admin/api/collections/{col}` теперь всегда возвращает `{ items, total, page, perPage, facets, metrics }`. Старый ответ плоским массивом удалён, в том числе у запросов без параметров. Читайте `response.items` и загружайте нужные страницы через `page`, `perPage` и `total`. Размер страницы по умолчанию 50, если не настроен иначе, максимум 200. `envelope` принимается для совместимости.
- `Mcp\AbstractMcpTool::locale()` теперь нестатический. Внутри методов экземпляра работают `self::locale($args)` и `$this->locale($args)`. Перенесите вызовы из статического контекста в метод экземпляра. Если класс сайта переопределяет `locale()` как `static`, уберите `static` из переопределения, иначе PHP не загрузит класс.
- При подключении `itk_cms.locales` у `main_locale` обрезаются пробелы и понижается регистр; код должен состоять из 2 или 3 строчных латинских букв и входить в список. Без `locales` прежнее значение сохраняется. Если на работающем сайте основной код нестандартный (`RU`, ` ru ` или `pt-BR`), выберите поддерживаемый код и до включения `locales` вручную перенесите сохранённые языковые значения и ключи JSON. Изменение конфига само по себе не переносит содержимое. Региональные метаданные задавайте в `html_lang` / `og_locale`.

Пример PostgreSQL ниже меняет точный старый код `RU` на `ru`. Подставьте оба значения по данным сайта; сначала проверьте резервную копию и разрешите конфликты, когда старый и новый коды уже сосуществуют (переводы страниц, настройки, меню, записи коллекций и исторические снимки). Обновления JSON намеренно пропускают строку, в которой уже есть новый ключ. Сохраните общие настройки (`locale = '*'`) и SEO-правила для всех языков (`locale IS NULL`). Отдельно проверьте таблицы и интеграции сайта. Это пример ручного обслуживания, а не миграция бандла.

```sql
BEGIN;
UPDATE itk_page_translation SET locale = 'ru' WHERE locale = 'RU';
UPDATE itk_setting SET locale = 'ru' WHERE locale = 'RU';
UPDATE itk_revision SET locale = 'ru' WHERE locale = 'RU';
UPDATE itk_seo_rule SET locale = 'ru' WHERE locale = 'RU';
UPDATE itk_menu_area
SET items = (items - 'RU') || jsonb_build_object('ru', items->'RU')
WHERE items ? 'RU' AND NOT (items ? 'ru');
UPDATE itk_collection_item
SET translations = (translations - 'RU') || jsonb_build_object('ru', translations->'RU')
WHERE translations ? 'RU' AND NOT (translations ? 'ru');

-- Исторические снимки удалённых целиком страниц и записей коллекций.
UPDATE itk_revision
SET snapshot = jsonb_set(snapshot, '{versions}',
    ((snapshot->'versions') - 'RU') || jsonb_build_object('ru', snapshot->'versions'->'RU'))
WHERE snapshot->'versions' ? 'RU' AND NOT (snapshot->'versions' ? 'ru');
UPDATE itk_revision
SET snapshot = jsonb_set(snapshot, '{translations}',
    ((snapshot->'translations') - 'RU') || jsonb_build_object('ru', snapshot->'translations'->'RU'))
WHERE snapshot->'translations' ? 'RU' AND NOT (snapshot->'translations' ? 'ru');
COMMIT;
```

### 0.2.0

- Удалён `Content\SettingsService::routesError()`. Если сайт его вызывает, уберите вызов. `SettingsService::save()` теперь принимает пустой чат для остальных форм, когда подключён Telegram или MAX. Если сайт рассчитывал на отказ, проверяйте это в коде сайта.

- Свой экран состояния или монитор, который читает `checks[].status` из API админки `health`, должен принимать новое значение `off`. Оно равно по весу `ok`.
