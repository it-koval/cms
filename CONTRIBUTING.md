# Участие в разработке

Спасибо, что заглянули в ITK CMS. Проект в альфе, поэтому полезнее всего сообщения об ошибках с описанием, как их воспроизвести, исправления с тестом и поправки в документации.

О проблеме безопасности не создавайте issue: см. [SECURITY.md](SECURITY.md).

## Устройство репозитория

- `packages/cms`: Composer-пакет `itk/cms` (бандл Symfony, его тесты, собранная админка).
- `admin`: исходники админки (Vue 3, Vite). Сборка попадает в `packages/cms/public/admin`.

## Настройка окружения

Понадобятся PHP 8.3 или новее с расширениями `ctype`, `dom`, `gd`, `json`, `mbstring`, `pdo_mysql`, `sodium` (и, желательно, `exif`), Composer, Node.js той версии, что указана в `admin/.nvmrc`, и Docker для тестовой базы данных.

Тесты выполняются на MySQL 8 и отправляют почту в Mailpit:

```bash
docker run -d --name itk-test-db -p 127.0.0.1:33950:3306 -e MYSQL_ROOT_PASSWORD=itk-test mysql:8.4
docker run -d --name itk-test-mail -p 127.0.0.1:33951:1025 -p 127.0.0.1:33952:8025 axllent/mailpit

cd packages/cms
composer install
cd ../../admin
npm ci
```

## Запуск проверок

PHP, из `packages/cms`:

```bash
export ITK_TEST_MAILPIT_URL=http://127.0.0.1:33952 ITK_TEST_MAILPIT_SMTP_PORT=33951
composer test        # пересоздаёт базу itk_test, применяет миграции, запускает itk:install, затем PHPUnit
composer stan        # PHPStan, уровень 5
composer cs          # PHP CS Fixer, только проверка; composer cs:fix применяет исправления
```

`DATABASE_URL` по умолчанию равен `mysql://root:itk-test@127.0.0.1:33950/itk?serverVersion=8.4&charset=utf8mb4` (тесты используют базу `itk_test`; в вашем собственном значении тоже нужен `serverVersion`, иначе `doctrine:database:create` завершится ошибкой `Unknown database`). Без `ITK_TEST_MAILPIT_URL` тесты почты пропускаются. Подробнее о тестах написано в разделе «Тесты бандла» файла [packages/cms/README.md](packages/cms/README.md).

Админка, из `admin`:

```bash
npm run lint
npm run check:i18n  # каталоги интерфейса и кириллица в коде
npm test
npm run build        # записывает сборку в packages/cms/public/admin
```

`npm run dev:mock` запускает админку без PHP, на выдуманных данных.

## Собранная админка хранится в репозитории

`packages/cms/public/admin` создаётся командой `npm run build` и хранится в git, чтобы сайту не требовался Node. Если вы что-то меняете в `admin/`, пересоберите админку и закоммитьте результат вместе с исходниками. CI пересобирает админку и падает, если `packages/cms/public/admin` отличается от закоммиченного. Не правьте собранные файлы вручную.

## Стиль кода

- Пишите так же, как код вокруг: имена, комментарии (на английском) и приёмы. Файлы PHP начинаются с `declare(strict_types=1);`, классы объявляются `final`, если их не предполагается расширять.
- Стиль PHP проверяет PHP CS Fixer по `.php-cs-fixer.dist.php` в корне репозитория.
- Текст, который человек видит в админке, в письмах, в консоли и в ответах API, не пишется в коде строкой: это ключ каталога на трёх языках (см. «Как добавить строку»). Не смешивайте языки внутри одного экрана.
- То, что бандл обещает сайтам, перечислено в [UPGRADE.md](UPGRADE.md). Не ломайте это без записи в журнале изменений.
- Не расширяйте изменение: исправление одного не должно переписывать соседнее.

## Как добавить строку интерфейса

Интерфейс говорит на английском, русском и казахском. Язык интерфейса не связан с языком содержимого сайта (`main_locale`, языковые версии страниц).

1. Придумайте ключ `область.ключ`: область (`pages`, `forms`, `content`, …) и snake_case после точки. Одно целое предложение, один ключ. Не склеивайте предложение из кусков и не вставляйте условие внутрь фразы: порядок слов в казахском другой, а род и падеж русского не передашь подстановкой. Нужны два варианта, заведите два ключа или ключ с параметром.
2. Добавьте ключ во все три каталога, значения с одинаковыми параметрами `{name}`.
   - Админка (Vue): `admin/src/i18n/{en,ru,kk}/<область>.json`. Вызов `t('area.key', { name: x })` из `@/i18n/index.js`, в шаблонах тоже `t(...)`. Число: `t('area.key', { count: n })`, а значение в JSON объект по категориям `Intl.PluralRules`: `one`, `few`, `many`, `other` для русского, `one`, `other` для английского, `other` для казахского. Даты, числа и сортировка идут через `formatDate`, `formatNumber`, `collator`.
   - Бандл (PHP): `packages/cms/translations/itk_<область>.{en,ru,kk}.yaml`, значения в одинарных кавычках. Вызов `Itk\Cms\I18n\I18n::t('area.key', ['name' => $x])`, в Twig `itk_t('area.key', {name: x})`. Множественное число: параметр `count` и формы через `|` (русский `{count} страница|{count} страницы|{count} страниц`, английский `{count} page|{count} pages`, казахский `{count} бет|{count} бет`).
3. Русский текст оставьте таким, каким он был: тесты сайта работают на русском. Английский: короткие подписи, первая буква заглавная, остальные строчные. Казахский: литературный язык интерфейса, кириллица. Термины держите теми же, что в соседних строках каталога (бет, жоба, жариялау, өтінім, баптаулар и так далее).
4. Не переводите то, что уходит в код или в API: ключи, статусы, адреса, имена полей, значения по умолчанию в данных сайта. Данные сайта, схема сайта и подписи, которые задал разработчик сайта, остаются как есть.
5. Проверьте: `npm run check:i18n` (из `admin/`) сверяет каталоги и ищет кириллицу в коде вне комментариев; `composer test` включает `I18nCatalogTest` и `I18nCyrillicTest`. Кириллица, которая должна остаться в коде (например, название языка на нём самом), помечается комментарием `i18n-ignore` в той же строке.

## Тесты

Сначала напишите тест и убедитесь, что он падает, затем меняйте код. Исправление ошибки сопровождается тестом, который без исправления падает. Тесты бандла лежат в `packages/cms/tests/Core`; тестовый сайт — в `packages/cms/tests/App`. Логика админки, которой не нужен DOM, проверяется Vitest рядом с кодом (`*.test.js`).

## Коммиты и pull request

- Одно логическое изменение на коммит. Короткая тема в повелительном наклонении (около 72 символов) и тело, которое объясняет, почему так, если причина неочевидна. Обязательного префикса нет.
- Добавьте запись в раздел «Не выпущено» файла [CHANGELOG.md](CHANGELOG.md) для всего, что заметит пользователь бандла.
- Перед тем как открыть pull request, запустите проверки выше. В описании укажите, что изменилось, почему и как вы это проверили.
