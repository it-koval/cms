# Админка ITK CMS (Vue 3 и Vite)

Админка это тонкий клиент к серверу `itk/cms`. Все данные идут через `fetch` в API админки (по умолчанию `/admin/api`). Адрес админки задаёт опция сайта `itk_cms.admin_path`, по умолчанию `/admin`, а клиент берёт все адреса из оболочки сервера. Сайт и его схема приходят с сервера.

## Команды

Команды npm запускаются из `admin/` в Docker через `docker compose run --rm node <команда>`. Для Vite используйте цели `make` из корня репозитория, указанные в таблице. Они публикуют порт контейнера. Контейнер работает на Node 24.22.2 (`.nvmrc`, `engines`, `admin/compose.yaml`) и хранит Linux-зависимости в отдельном volume, отдельно от `node_modules` хоста. Менять Node или PHP на хосте не нужно.

| Команда | Что делает |
|---|---|
| `npm ci` | Ставит зависимости из lock-файла. |
| `make admin-dev` из корня репозитория | Запускает `npm run dev` в Docker. Vite доступен на `http://127.0.0.1:18023/bundles/itkcms/admin/` и проксирует API на сайт. См. [Разработка без оболочки сервера](#разработка-без-оболочки-сервера). |
| `make admin-mock` из корня репозитория | Запускает `npm run dev:mock` в Docker. Админка доступна на порту 18023 без PHP, на выдуманных данных. См. [Режим мока](#режим-мока). |
| `npm run lint` | ESLint 9. |
| `npm run check:i18n` | Проверяет каталоги интерфейса. См. [Язык интерфейса](#язык-интерфейса). |
| `npm test` | Vitest. |
| `npm run build` | Записывает админку в `packages/cms/public/admin` вместе с `.vite/manifest.json`. Затем сайт выполняет `bin/console assets:install`. |

## Оболочка сервера

`packages/cms/templates/admin/index.html.twig` рисует страницу и читает манифест Vite. Она задаёт `window.ITK_ADMIN`:

```js
window.ITK_ADMIN = {
  adminBase, apiBase, csrf, user, site: { name, domain }, mainLocale,
  siteTexts: { item, section }, locale, locales: [{ code, name }],
  previewBase, loginUrl, logoutUrl, assetsBase,
  images: { uploadUrl, variantDir, widths }, theme,
}
```

- `locale` это язык интерфейса текущего пользователя, на нём работает `t()`. `locales` перечисляет языки, из которых пользователь выбирает, каждый назван на самом себе.
- `mainLocale` это язык содержимого сайта, а не интерфейса.
- `siteTexts` содержит названия нового элемента и новой секции по умолчанию, на языке содержимого.
- `theme` содержит цвета и скругления. См. [Оформление](#оформление).

## Где что лежит

- `api/` это клиент API. `http.js` оборачивает `fetch`, отправляет CSRF-токен в `X-CSRF-Token` и превращает ответы `{error, details}` в `ApiError`. На каждую область свой модуль (`pages`, `collections`, `requests`, `media`, `settings`, `users`, `site` и другие). Комментарий над каждой функцией называет её endpoint.
- `schema/` хранит схему сайта. `registry.js` загружает `GET /admin/api/schema` в один объект `schema` до запуска приложения. Остальные файлы содержат общую логику поверх него: шаблоны и правила размещения, правило H1, библиотеку секций, настройки и области меню.
- `i18n/` это язык интерфейса. См. [Язык интерфейса](#язык-интерфейса).
- `stores/app.js` хранит сайт, языки, текущего пользователя и его права (`can(area, action, {template})`) и счётчики в рельсе.
- `views/SettingsView.vue` и `components/settings/` это экран настроек. `NAV` в `settingsSchema.js` задаёт меню слева: пять заголовков и одиннадцать пунктов (Основное, Меню, Переадресации, SEO, Уведомления, Боты, Почта, Пользователи и роли, ИИ-ассистенты, Оформление админки и Шаблоны под заголовком «Разработчику»). **Основное** показывает все группы настроек схемы сайта на одной странице, по карточке на группу, права проверяются по карточкам.
- `components/editor/` это редактор страницы. Холст это `PreviewFrame.vue`, iframe с `/admin/preview/{id}`, где сервер рисует черновик шаблонами сайта. Холст и редактор общаются через `postMessage` (`itk:focus`, `itk:action`, `itk:select`, `itk:reload`, см. `packages/cms/public/preview.js`). После автосохранения iframe перезагружается и сохраняет прокрутку.
- Переключатель языка скрыт, пока у сайта один язык.
- `layouts/AppLayout.vue` это рельса слева. Её строит сервер (`GET /admin/api/schema` возвращает `nav`, он хранится в `app.nav`):

  ```js
  [{ key, group, icon, order, items: [{ key, label, to, icon, order, badge?, sub? }] }]
  ```

  Список уже отсортирован и очищен до того, что пользователю можно открыть. Группа с названием получает маленький заголовок. `sub: true` помечает быструю ссылку под предыдущим пунктом. Рельса подсвечивает самый точный пункт для текущего адреса. Число у пункта берётся из `app.badges[key]`, если оно есть, иначе из `badge` сервера. Новый класс ресурса или `NavItem` расширения появляется в рельсе сам. Иконки лежат в `components/ui/icons.js`. Незнакомое имя иконки рисует значок документа.

## Оформление

Сервер (`Admin\Theme\AdminTheme`) вычисляет цвета и скругления и вставляет их в оболочку как CSS-переменные до первой отрисовки. В стилях админки нет зашитых цветов бренда и акцента, только токены: `--cy*`, `--mag*`, `--brand-ink` для текста на цвете бренда, `--brand-text` для надписей цветом бренда на светлом фоне и `--rail-shade`. Список токенов в `styles/tokens.css`.

`utils/theme.js` применяет ответ `/admin-theme` к открытой странице. Экран это `components/settings/ThemePanel.vue` с `ThemeColor.vue`, клиент это `api/theme.js`. В новых стилях пишите цвета бренда и акцента токенами, а для текста на цвете бренда используйте `var(--brand-ink)`, а не `#fff`.

## Превью картинок

Каждый `<img>` с картинкой из медиатеки (в полях, карточках, списках, ящике файла и редакторе текста) получает адрес через `thumbUrl(src, ширина)` из `utils/media.js`. Ширина 320 (`THUMB`) для маленьких превью, 640 (`PREVIEW`) для карточек и ящика файла и 960 в тексте статьи. Помощник строит адрес WebP-копии по `window.ITK_ADMIN.images` по той же схеме, что `ImageVariants::url` на сервере. GIF, SVG, PDF, чужие адреса и `npm run dev` (в нём нет настроек картинок) остаются с исходным адресом. Сохранённые значения не меняются, меняется только показ. Новый `<img>` с картинкой из медиатеки пишите так же.

## Список коллекции

Список знает только то, что сообщает схема коллекции (`cfg`). Кодов коллекций в нём нет. Файлы: `components/collections/CollectionList.vue`, `list/` и `actions/`.

- **Данные.** `api.collections.query(col, { q, filter, sort, page, perPage })` возвращает `{ items, total, page, perPage, facets, metrics }`. Поиск, фильтры, сортировку и страницы делает база. Фильтр уходит как `filter[status]=…&filter[date][from]=…`, сортировка как `sort=-dateStart`.
- **Панель фильтров.** `list/ListFilters.vue` рисует элемент для каждого поля с `field.filter = { kind, options }`, которое сервер присылает для полей с `filterable()`. Виды: `text`, `select`, `multi`, `toggle`, `dateRange`, `numberRange` и `relation`. Фильтр по статусу есть у каждой коллекции. Незнакомый вид отбрасывается. `facets` показывают, сколько записей с каждым значением.
- **Колонки и сортировка.** Сначала название, затем поля с `list.show === true` (или `null` у сортируемых полей). `hideOnIndex` на сервере превращается в `list.show === false`. Клик по заголовку сортируемой колонки переключает: по возрастанию, по убыванию, без сортировки. `list/CellValue.vue` выбирает вид ячейки по типу значения.
- **Метрики.** `list/ListMetrics.vue` рисует плитки над списком из `Metric::count` и `Metric::sum` ресурса.
- **Состояние.** `list/useListState.js` сохраняет фильтры, сортировку, размер страницы и вид на сервере для каждого пользователя (`api.prefs`, ключ `list.<коллекция>`, `GET` и `PUT /admin/api/prefs/{key}`). Они возвращаются при следующем заходе с любого устройства. Поиск и номер страницы не сохраняются. Сохранённые значения полей, которых больше нет, отбрасываются при чтении (`sanitizeSaved`). Если сервер всё равно отказал (422), список открывается без фильтров.
- **Права на поля.** Поля, которые пользователю нельзя видеть, сервер не присылает, и клиент работает без них: нет колонки, нет значения. `hideOnForm` превращается в `form: false` (форма не рисует поле). `readonly` превращается в `ro: true` (поле рисуется, но не правится).

## Дерево, календарь и доска

Эти три компонента ничего не знают о конкретном сайте. Где можно, их логика вынесена из Vue, чтобы её можно было проверить без браузера.

### `components/ui/SortableTree.vue` и `treeOps.js`

Дерево, узлы которого переносят перетаскиванием за значок (перетаскивается только значок, потому что в строках бывают поля ввода) или с клавиатуры (Alt со стрелками и кнопки «Выше», «Ниже», «Вложить», «Вынести»).

- Дерево вложенное: `[{ id, …, children: [...] }]`. `treeOps.nest(плоский список с parentId)` собирает его. Пропсы `id-key` и `kids-key` переименовывают ключи.
- Пропсы:
  - `max-depth`: число уровней, начиная с 1. Узел считается вместе со всей своей веткой.
  - `can-drop({ node, parent, index, nodes })`: возвращает `true`, `false` или строку с причиной. Вызывается после встроенных правил (не в себя, не в свою ветку, глубина).
  - `locked(node)`: узел стоит на месте, например главная страница.
  - `tools`: кнопки в строке.
  - `bare`: строка без своей рамки.
  - `foldable` и `disabled`.
- Компонент сам ничего не меняет. Событие `move({ id, node, parentId, index, from, to, nodes, groups })` отдаёт новое дерево родителю, тот сохраняет его и возвращает дерево назад. `invalid(причина)` сообщает о запрещённом переносе.
- `treeOps.payload(nodes, groups)` собирает `[{ id, parentId, position }]` для соседей под старым и новым родителем.
- Зоны сброса на строке: верхняя треть кладёт перед строкой, нижняя после неё (у раскрытой ветки первым вложенным), середина внутрь. Запрещённое место показывает красную рамку и причину под деревом. Живая область сообщает читалкам экрана, где теперь узел.
- Где используется: **Страницы → Изменить структуру** (`api.pages.tree`, правила размещения из `canPlace` в `schema/templates.js`, отмена во всплывающем сообщении), пункты меню (`components/settings/MenusEditor.vue`, глубина из области меню) и вид **Структура** коллекции с `tree()` (`api.collections.tree`).

### `components/collections/list/CalendarView.vue` и `calendarModel.js`

- Вид месяца или недели. Неделя начинается с понедельника. Дни это строки `YYYY-MM-DD`, они считаются в UTC, поэтому перевод часов ничего не сдвигает.
- Пропсы `start` и `end` это ключи полей из настроек вида.
- События: `create(day)` (клик по дню или по «+») и `move({ row, start, end, days })` (перетаскивание или Alt со стрелками сдвигает обе даты на одно и то же число дней и сохраняет время суток).
- `CollectionList.vue` сохраняет перенос обычным `api.collections.update` черновика. Строка меняется на экране сразу и возвращается назад, если сервер отказал. Всплывающее сообщение предлагает отмену.
- В ячейке месяца три записи. «Ещё N» открывает неделю этого дня.

### `components/ui/KanbanBoard.vue`

- Колонки строятся по значениям: `columns: [{ value, label }]` и `column-of(item)`.
- Карточка переносится перетаскиванием или кнопками со стрелками (Alt с влево или вправо). Событие `move({ item, from, to })`. Порядок внутри колонки не хранится. Слот `card` рисует карточку.
- Используется в списке коллекции (вид `kanban` из схемы, по полю `select`) и на экране **Заявки** (вид «Доска» с колонками «Новая», «В работе» и «Закрыта»; статус меняет `api.requests.update`; спам на доске не показан).

### Переключатель видов

`viewsOf(cfg)` из `list/listModel.js` строит переключатель над списком коллекции: `table`, `cards`, `calendar` и `kanban` из `views` схемы, а также `tree`, если у коллекции есть `tree()`. Календарь, доска и дерево загружают все записи сразу (`queryAll`, порциями по 200, до 2000) и обходятся без пейджера. Выбранный вид сохраняется вместе с остальным состоянием списка (`api.prefs`). На экране **Заявки** он сохраняется под ключом `requests.view`.

## Слова сайта берутся из схемы

В админке нет названия ни одного сайта и ни одного предмета его торговли. То, что видит пользователь, приходит из схемы (`schema/*`). Общие слова лежат в `components/collections/labels.js` и `utils/format.js`.

- **Переключатель строки в списке.** Коллекция называет поле переключателя в `cfg.toggleField`. `toggleLabelOf(cfg)` из `labels.js` берёт подпись самого поля, например «На главной». Поле без подписи называется «Показывать». Этим именем подписаны заголовок колонки и всплывающее сообщение после щелчка (`toggleNote()`).
- **Переключатель страницы в списке родителя.** `listingSwitch(шаблон)` из `schema/templates.js` находит поле, которое шаблон родителя называет в `listing.onlyIf` (`->listing(of: [...], onlyIf: 'show')`), и берёт его подпись. Сайт без `onlyIf`, у страниц которого есть переключатель с ключом `catalog`, использует это поле. Та же функция рисует колонку в плоском списке страниц (`PagesView.vue`) и предупреждение «Не показывается в списке» на карточке страницы (`components/editor/TemplateCard.vue`).
- **Таблица опций.** Вид `view: 'matrix'` (`components/collections/MatrixView.vue` с `matrixChanges.js`, слова в `schema/matrix.js`) по умолчанию говорит общими словами («столбец», «строка», «Новый столбец»). Коллекция задаёт свои слова так:
  - `cfg.newLabel`: только подпись кнопки добавления, глагольная фраза вроде «Добавить тариф».
  - `cfg.description`: строка под заголовком.
  - `cfg.matrix.colFields[1].label`: название строки с ценой.
  - `cfg.matrix.words = { colNew, colPlural: ['тариф', 'тарифа', 'тарифов'], rowNew, … }`: любая фраза из `MATRIX_WORDS`, с подстановкой `{name}`. Имя нового столбца («Новый тариф») задаётся только здесь, в `colNew`. Значение неверного типа отбрасывается.
- **Перенесённые страницы.** Страница, перенесённая с сайта, который был до CMS, вместо даты изменения показывает пометку о переносе, пока её не отредактируют (`MIGRATED_NOTE` в `utils/format.js`).

## История и корзина

- `api/history.js` покрывает `GET history/:kind/:id`, `GET history/revision/:id`, `POST history/revision/:id/restore` и `GET history/trash`.
- `components/history/HistoryDrawer.vue` это боковая панель **История**. Она показывает, кто, когда и что изменил. Запись раскрывается и показывает, что она изменила и что изменится, если её вернуть. **Вернуть эту версию** просит подтверждения.
- `ChangeRows.vue` рисует строки изменений, `historyWords.js` называет действия.
- Панель принимает `kind` (`page`, `item`, `settings` или `menu`), `resource-id`, `locale` и `can-restore` и отправляет событие `restored`. После него экран заново читает черновик (`ed.reloadDraft()` в редакторе страницы, `load()` у записи).
- Кнопка стоит в `EditorTopBar.vue` и в шапке `CollectionItemView.vue`. Перед открытием панели экран досохраняет автосохранение.
- `views/TrashView.vue` (`/trash?kind=&key=`) это экран **Корзина** с удалёнными страницами и записями. **Вернуть** открывает вернувшееся как черновик. Ссылки на корзину есть в **Страницах** и в списке коллекции.

## Уведомления

- `api/notifications.js` покрывает `GET notifications?unread=1&limit=&offset=` и `POST notifications/read` с `{ ids }` или `{ all: true }`.
- `stores/notifications.js` хранит число непрочитанных и список панели и опрашивает сервер раз в 60 секунд, пока вкладка открыта.
- `components/notifications/NotificationBell.vue` это кнопка-колокольчик в блоке сайта в рельсе со счётчиком и боковой панелью **Уведомления** («Все» или «Непрочитанные» и «Отметить всё прочитанным»). Каждая строка показывает заголовок, подробности и время.
- Клик по строке отмечает её прочитанной и ведёт по ссылке. Маршрут админки (`/requests/12`) открывается через роутер. Полный адрес открывается в новой вкладке.
- Что видит каждый пользователь, решает сервер по правам и роли. Клиент ничего не фильтрует.

## Действия

`Action::make(...)` в классе ресурса попадает в `cfg.actions`:

```js
{ key, label, icon?, danger?, confirm?, modal?: { title, fields }, places: ['row', 'bulk', 'top', 'form'] }
```

Сервер уже убрал действия, которые пользователю нельзя запускать. `components/collections/actions/useActions.js` обрабатывает их:

- Места: `top` ставит кнопки в шапку списка, `bulk` на панель над таблицей, когда отмечены строки, `row` в меню строки, `form` в меню **Действия** на странице записи (перед запуском черновик сохраняется).
- `confirm` открывает окно подтверждения. `modal` открывает окно с полями. `ActionDialog.vue` рисует их тем же `SchemaForm`, что и формы записей, и проверяет обязательные поля до отправки.
- Ответ `ActionResult`: `message` показывает всплывающее сообщение, `reload` перечитывает список, `redirect` открывает адрес админки через роутер или внешний адрес `http…` в браузере, `download` скачивает файл. Действие, которое само отдаёт файл, приходит как `{ file, blob, name }`, и файл сохраняется. Отказ (422) показывается ошибкой, окно остаётся открытым.

## Плагины админки (`window.ITK`)

Пакет сайта подключает свой скрипт на сервере через `Registry::adminAssets(js: [...], css: [...])`.

Как загружаются плагины:

1. Оболочка объявляет заглушку `window.ITK = { plugins: [], registerPlugin }` до основного бандла и держит скрипты плагинов неактивными в `<template id="itk-plugins">`.
2. Админка загружает язык и свой код, затем строит `window.ITK` (`plugins/registry.js` забирает то, что собрала заглушка).
3. Админка запускает скрипты плагинов по порядку (`plugins/scripts.js`), поэтому плагин может читать `ITK.vue` уже в первой строке. `plugins/state.js` хранит то, что зарегистрировали плагины. Реестр реактивный, поэтому плагин, пришедший после первого экрана, тоже подхватывается.

Первый экран ждёт скрипты плагинов. `start.js` строит приложение, когда загрузились (или упали) код админки и все скрипты плагинов. Зависший скрипт задерживает первый экран до таймаута `WAIT` в `plugins/scripts.js` (8000 мс). После этого админка стартует без него, а опоздавший скрипт всё равно зарегистрируется. `registerPlugin` работает сразу. Сломанное описание пропускается и не ломает админку. Плагин, виджет которого упал при отрисовке, пропадает с экрана, остальное работает.

### Версия контракта

`ITK.version` это строка semver (`ITK_VERSION` в `plugins/state.js`). Минорная версия что-то добавляет. Мажорная меняет или убирает то, на что мог опираться плагин. Плагин может проверить версию перед стартом: `if (!window.ITK || parseInt(ITK.version) !== 1) return`.

`admin/types/itk.d.ts` описывает типы всего контракта. Пакет админки приватный и в `node_modules` плагина не попадает. Скопируйте файл в проект плагина (например, в `types/itk.d.ts`) и добавьте его в `include` в `tsconfig.json` или `jsconfig.json` либо добавьте `/// <reference path="../types/itk.d.ts" />` с относительным путём. После этого глобальная `ITK` и `window.ITK` типизированы во всём проекте без импорта.

### Регистрация плагина

```js
window.ITK.registerPlugin({
  // Свой тип поля: поле схемы с t: 'color' рисует этот компонент. Он принимает те же props и события,
  // что и встроенные поля (ITK.ui.fieldProps и fieldEmits, components/form/fieldProps.js).
  // Необязательная функция cell(value, field) у компонента даёт текст для колонки списка.
  fields: { color: ColorField },
  // Свой экран: пункт меню NavItem::make('Reports', '/x/reports') открывает #/x/reports этим компонентом (props: path, query).
  panels: { reports: ReportsPanel },
  // Клиентская часть действия: 'ресурс:действие' или просто 'действие'. Функция получает
  // { resource, action, ids, records, locale, run(input), done(result), toast, http } и может вернуть объект вроде ActionResult.
  // { modal: Component } рисует компонент в окне (props: resource, action, ids, close(), run(input)).
  actions: { 'tours:export': async (ctx) => ctx.run({ format: 'csv' }) },
  // Своя карточка записи на её странице, справа от формы, по ключу коллекции. Props: cfg (схема коллекции), data (черновик).
  // Без неё ядро рисует простую карточку: картинка (thumbField), заголовок (titleField), подзаголовок (subField).
  previews: { tours: TourCard },
  // Блок на экране «Сегодня», под встроенными секциями. Компонент рисует свою карточку (.sheet). Props: locale.
  // Блоки идут в порядке регистрации. Виджет, упавший при отрисовке, скрывается, причина остаётся в консоли.
  widgets: { stats: StatsCard },
  // Кнопка в шапке редактора страницы, после «Предпросмотр» (на телефоне в меню «⋯»).
  editorActions: {
    check: {
      label: 'Check', icon: 'check', title: 'Check the page before publishing', order: 10,
      when: (ctx) => ctx.template === 'blog_article', // необязательно: false прячет кнопку для этой страницы
      run: async (ctx) => { const r = await ctx.http.post(`x/check/${ctx.pageId}`); ctx.toast.show(r.ok ? 'All good' : r.message) },
    },
  },
})

// Свой маршрут: #/reports/12. Путь начинается с «/», и его первая часть не может совпадать с разделом админки
// (pages, collections, requests, media, settings, trash, health, x). Такой маршрут отклоняется с причиной в консоли.
// Возвращает функцию, которая убирает маршрут, или null. meta.layout: 'app' (внутри рельсы, по умолчанию) или 'bare'. meta.title: заголовок вкладки.
const remove = window.ITK.addRoute({ path: '/reports/:id?', component: ReportPage, meta: { title: 'Report' } })
```

**Кнопки редактора** (`editorActions`) это объекты `{ label, run(ctx), icon?, title?, order?, when?(ctx) }`. Кнопка без `label` или без `run` пропускается, причина пишется в консоль. Перед `run` админка досохраняет автосохранение. В `ctx` есть `pageId`, `locale`, `title`, `status` (`published`, `draft` или `changed`), `template`, `readOnly`, `page` (копия черновика, читается по требованию), `flush()`, `reload()` (перечитывает черновик после своих правок через `ctx.http`), `toast` и `http`. Ошибка из `run` показывается всплывающим сообщением.

**Маршруты** (`ITK.addRoute`): скрипт плагина загружается после бандла, а пользователь мог открыть `#/reports` раньше. К этому моменту роутер уже отправил его на **Сегодня**, потому что адрес был неизвестен. Когда маршрут появляется, пользователя переводят туда, куда он шёл. Если нужен только пункт меню, проще `panels` вместе с `NavItem::make('Reports', '/x/reports')`. `addRoute` отклоняет маршрут и возвращает `null` с причиной в консоли, если:

- путь начинается с раздела админки;
- у `component` есть опция `template` без `render` (экран был бы пустым);
- `name` совпадает с именем маршрута ядра (`today`, `pages` и другие), потому что vue-router заменил бы маршрут админки.

### Что доступно плагину

- `ITK.version`: версия контракта.
- `ITK.vue`: весь Vue (`import * as Vue`): `h`, `ref`, `reactive`, `computed`, `watch`, `defineComponent` и всё, что импортируют собранные `.vue` (`openBlock`, `createElementBlock`, `createVNode`, `toDisplayString`, `withCtx`, `normalizeClass` и другие). Это тот же экземпляр Vue, что у админки, реактивность общая.
- `ITK.http`: клиент API с CSRF (`get`, `post`, `put`, `patch`, `del`, `upload`). Также `ITK.toast` (`show`, `error`), `ITK.confirm({ title, message, confirmLabel, danger })`, который возвращает `Promise<boolean>`, и `ITK.addRoute`.
- `ITK.i18n`: язык интерфейса. В нём есть `t(key, params)`, `locale` и `add(locale, messages)` для собственных текстов плагина, например `add('en', { 'reports.title': 'Reports' })` и `add('ru', { 'reports.title': 'Отчёты' })`. Форма числа задаётся объектом `{ one, few, many, other }`. При смене языка страница перезагружается, поэтому реактивность не нужна. Скрипты плагинов запускаются после загрузки языка и кода админки, поэтому `ITK` готов с первой строки плагина. По той же причине `add` может заменить ключ админки только для вызовов `t()` после старта: константы модулей (меню, схемы) уже вычислены.
- `ITK.ui`: готовые компоненты админки. Их props и события смотрите в файлах компонентов в `components/ui/` и `components/form/`.

  | Имя | Что это |
  |---|---|
  | `Modal`, `Drawer`, `Popover` | Окно по центру (`v-model:open`, `title`, слот `footer`), правая боковая панель и меню у кнопки (`anchor`, `align`). |
  | `ConfirmDialog` | Окно, которое открывает `ITK.confirm()`. Оно уже один раз стоит на странице. Вызывайте `ITK.confirm()`, а не рисуйте своё. |
  | `SchemaForm` | Форма по описанию полей (`schema`, `v-model`, `published`, `readonly`), как формы записей и действий. |
  | `FieldShell`, `FieldRenderer` | Обёртка поля (подпись, подсказка, ошибка) и выбор компонента по `field.t`, в том числе вашего типа. |
  | `TextField`, `TextareaField`, `HeadlineField`, `NumberField`, `ToggleField`, `SelectField`, `ImageField`, `LinkField` | Базовые поля. |
  | `fieldProps`, `fieldEmits` | Props и события, которые принимает компонент поля. |
  | `Icon`, `SortableTree`, `KanbanBoard` | Значок по имени (`components/ui/icons.js`), дерево и доска. |

- Классы из `styles/base.css` уже есть на странице: `.page` (экран внутри рельсы: `max-width` и отступы) с `.page-h` (шапка: `h1`, `.sub`, `.actions`), `.sheet` (белая карточка), `.btn` (с `primary`, `ghost`, `danger`, `sm`, `icon`), `.alert` (с `info-a`, `warn-a`, `err-a`), `.chip`, `.muted` и `.sr` (только для читалок экрана). Цвета и отступы берите токенами (`var(--ink)`, `var(--cy)`, `var(--hair)` и другие из `styles/tokens.css`), а не числами: тема сайта их меняет.

### Как собрать плагин из `.vue`

Плагину на `h()` сборка не нужна. Чтобы использовать файлы `.vue`, соберите их Vite и оставьте `vue` внешним, он берётся из `ITK.vue`. Скрипт загружается как `type="module"` в формате `iife`:

```js
// vite.config.js плагина
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [vue()],
  define: { 'process.env.NODE_ENV': '"production"' }, // в режиме библиотеки Vite его не подставляет
  build: {
    // Стили из <style> попадут в admin.css рядом с admin.js (без cssFileName файл назвали бы по имени пакета).
    // Подключите оба через Registry::adminAssets(js: [...], css: [...]).
    lib: { entry: 'src/plugin.js', name: 'MyPlugin', formats: ['iife'], fileName: () => 'admin.js', cssFileName: 'admin' },
    rollupOptions: { external: ['vue'], output: { globals: { vue: 'ITK.vue' } } },
  },
})
```

`src/plugin.js` вызывает `window.ITK.registerPlugin({...})`. Не кладите Vue в бандл плагина: второй экземпляр Vue ломает реактивность и `provide` с `inject`.

Опция `template:` без сборки не работает. Админка поставляется с Vue без компилятора шаблонов, поэтому `{ template: '<b>x</b>' }` ничего не нарисует. Админка пишет предупреждение в консоль, и в разработке, и в продакшене, и не регистрирует такой компонент. Напишите функцию `render()` на `h()` из `ITK.vue` или соберите `.vue`, как показано выше.

## Язык интерфейса

`i18n/index.js` экспортирует `t`, `locale`, `formatDate`, `formatNumber` и `collator`:

```js
import { t, locale, formatDate, formatNumber, collator } from '@/i18n/index.js'
```

- Тексты лежат в `i18n/<locale>/<area>.json`. Ключи плоские: `"area.key"`, после точки snake_case.
- Параметры: `t('area.key', { name: x })` подставляет `{name}`.
- Множественное число: `t('area.key', { count: n })`. Значение в JSON это объект по категориям `Intl.PluralRules`: `{"one":…,"few":…,"many":…,"other":…}` для `ru`, `{"one":…,"other":…}` для `en` и `{"other":…}` для `kk`.
- Если ключа нет в языке, берётся английский текст. Если нет и его, `t()` возвращает сам ключ и пишет `console.warn` в разработке.
- Даты, числа и сортировку форматируйте через `formatDate`, `formatNumber` и `collator` (`list.sort(collator.compare)` или `collator({ numeric: true }).compare`), а не через `'ru-RU'` или `localeCompare`. `formatDate` на пустой (`null`, `undefined`, `''`) или неверной дате возвращает пустую строку и не бросает ошибку.
- В части сборок Chrome нет данных Intl для `kk`, хотя `supportedLocalesOf` отвечает, что язык поддерживается. `initI18n` это проверяет (`hasIntlData`). Если данных нет, казахские даты показываются числами (`02.11.2026`, без названий месяцев и дней), а числа и сортировка идут через `ru`. Полифил не подключается.

`main.js` сначала загружает чанк языка (и английский за ним), потом динамически импортирует `start.js` со всем приложением, поэтому `t()` работает и на верхнем уровне модуля. Смена языка перезагружает страницу.

Язык приходит в `window.ITK_ADMIN.locale`. `setLocale(code)` сохраняет выбор пользователя (`PUT me/locale`, окно **Мой профиль**). В `npm run dev` и `npm run dev:mock` оболочки нет, поэтому язык хранится в `localStorage`, по умолчанию английский.

Скрипт холста редактора (`packages/cms/public/preview.js`) работает внутри страницы сайта, каталога у него нет. Маршрут `itk_admin_preview` рисует страницу на её собственном языке, как её увидит посетитель. Слова панели над секцией приходят в `window.ITK_PREVIEW.texts`: `PreviewController::texts()` собирает их на языке пользователя из `translations/itk_preview.<locale>.yaml`, а скрипт читает их через `say(name, label)`. Чтобы добавить слово, добавьте его в каталог и в `texts()`. `check:i18n` проверяет `preview.js` на кириллицу.

### Проверка каталогов

`npm run check:i18n` (`scripts/check-i18n.mjs`) проверяет каталоги админки и бандла:

- одинаковые ключи и параметры во всех языках;
- формы числа (если они есть у ключа в одном языке, они нужны во всех);
- ключи, которые используются в `t()`, `I18n::t()` и `itk_t()`;
- неиспользуемые ключи;
- кириллицу вне комментариев.

Скрипт в `package.json` запускается с `--strict`, и неиспользуемый ключ из предупреждения становится ошибкой. CI запускает `npm run check:i18n`. `--area=<имя>` проверяет одну область. `--warn-cyrillic=<путь>` только перечисляет кириллицу под путём. Ключ, собранный из кусков, распознаётся по литеральной части. Если её нет, добавьте комментарий `i18n-dynamic: area.prefix_`. Чтобы намеренно оставить кириллицу в коде, добавьте комментарий `i18n-ignore` в строке или запись в `scripts/check-i18n.allow.json`.

## Разработка без оболочки сервера

`npm run dev` проксирует `/admin/*` (или путь из `VITE_ITK_ADMIN_PATH`, если сайт перенёс админку), `/bundles/itkcms/*` (кроме `admin/`), `/build` и `/uploads` на сайт по адресу `ITK_SITE_URL` (по умолчанию `http://localhost:8080`). Сначала войдите на `/admin/login` сайта. Cookie сессии общая для портов одного хоста.

В этом режиме страница не получает `window.ITK_ADMIN` от сервера, поэтому `api/http.js` берёт запасные значения: `/admin` (или `VITE_ITK_ADMIN_PATH`) и CSRF-токен из `GET /me`. `MetaController::me()` возвращает `csrf`, тот же токен, который оболочка кладёт в `window.ITK_ADMIN.csrf` (HMAC пользователя и сессии). Его получает только вошедший пользователь. Если запись получила отказ 403 `{ details: { code: 'csrf' } }`, клиент объясняет причину (`DEV_CSRF_HINT` в `api/http.js`), а не показывает «Страница устарела».

## Режим мока

`npm run dev:mock` (то же, что `VITE_MOCK=1 npm run dev`; `.env.mock` включает его для `vite --mode mock`) показывает экраны без PHP и без базы.

- `main.js` вызывает `mock/install.js`, который перехватывает `fetch` для `/admin/api/*`. `mock/handler.js` отвечает данными из `mock/fixtures.js`: выдуманный демо-сайт с секциями и шаблонами, 8 страниц, коллекция «Новости» и таблица опций «Тарифы».
- Мок покрывает, среди прочих маршрутов, страницы, коллекции, заявки, настройки уведомлений и ботов, `robots.txt` и `llms.txt` и Яндекс Вебмастер. На неподдерживаемые маршруты он отвечает 404 с пояснением, что в демо этого нет. Экран, на который у роли из фикстуры нет прав, показывает «Нет доступа».
- Запись идёт в память вкладки (черновик, публикация, отмена правок, создание, удаление, перенос в дереве). Перезагрузка страницы возвращает фикстуры.
- Предпросмотр страницы это заглушка, потому что обычно его рисуют шаблоны сайта.
- Мок не попадает в `npm run build`: ветка в `main.js` вырезается, когда переменная не задана.
- Обработчик это чистый код с тестами (`mock/handler.test.js`). Новый экран, которому нужен ответ, добавляется в `handler.js` и `fixtures.js`.

## Инструменты

- **Линтер.** `npm run lint` запускает ESLint 9 с плоским конфигом `eslint.config.js`, `eslint-plugin-vue` (набор `essential`) и `@eslint/js`. Он сообщает только об ошибках, правил оформления нет. Prettier нет: оформляйте код так же, как код вокруг.
- **Тесты.** `npm test` запускает Vitest, по умолчанию в окружении `node`. Тесты компонентов редактора используют `jsdom` через директиву `@vitest-environment`. Тесты покрывают чистую логику и поведение rich text. Тест лежит рядом со своим файлом как `*.test.js`. CI также запускает `npm audit` и `npm audit --omit=dev`.
- **Сборка.** `npm run build` (Vite 6) записывает админку в `packages/cms/public/admin`. Чтобы проверить сборку, не трогая каталог пакета, выполните `npx vite build --outDir /tmp/itk-admin-check --emptyOutDir`.

### Чанки

- Tiptap и ProseMirror вынесены в отдельный именованный чанк `tiptap` (`manualChunks` в `vite.config.js`) и не загружаются на экранах без редактора. `TextareaField` и `HeadlineField` загружают его через обёртку `form/RichTextAsync.js`. Не импортируйте `RichText.vue` напрямую из кода, который попадает в основной бандл.
- Экраны, которые ставят фокус в такие поля (редактор страницы и запись коллекции), загружают чанк вместе с маршрутом (`withRichText` в `router/index.js`). Поле тогда сразу рисуется с редактором, и первый щелчок по тексту на холсте попадает в него. На остальных экранах чанк загружается с первым полем rich text.
- Vue лежит в своём чанке `vue`. Иначе Rollup кладёт рантайм туда, откуда его берёт чанк Tiptap, и редактор загружается на каждом экране.
- Проверка после изменения: в собранном `index.html` нет `modulepreload` на `tiptap`, у `index.html` в `.vite/manifest.json` в `imports` только `vue`, в чанке `tiptap` нет рантайма Vue.
- Предупреждение о размере чанка (`chunkSizeWarningLimit`) выставлено на 900 кБ.
