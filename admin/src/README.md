# Админка ITK CMS (Vue 3 + Vite)

Тонкий клиент к серверу пакета `itk/cms`: все данные идут по `fetch` в `/admin/api` (адрес админки — опция сайта `itk_cms.admin_path`, по умолчанию `/admin`; клиент берёт все адреса из оболочки), сайт и схема приходят с сервера.

- **Сборка:** `npm run build` → `../packages/cms/public/admin` (+ `.vite/manifest.json`, его читает `templates/admin/index.html.twig`). Потом на сайте `bin/console assets:install`.
- **Разработка:** `npm run dev` → http://127.0.0.1:5174/bundles/itkcms/admin/ . Запросы `/admin/*` (или путь из `VITE_ITK_ADMIN_PATH`, если сайт поставил админку не на `/admin`), `/bundles/itkcms/*` (кроме `admin/`), `/build`, `/uploads` уходят на сайт (`ITK_SITE_URL`, по умолчанию http://localhost:8080). Войдите на `/admin/login` сайта: cookie сессии общая для портов одного хоста. Подробности, в том числе про запись и CSRF, ниже в разделе «Разработка без оболочки сервера».
- **Без PHP:** `npm run dev:mock` (то же, что `VITE_MOCK=1 npm run dev`): API отвечает браузер, данные выдуманные, запись живёт в памяти вкладки. См. раздел «Режим VITE_MOCK».
- **Проверки:** `npm run lint` (ESLint 9), `npm test` (Vitest), `npm run build`. Нужен Node 18.18 или новее (`.nvmrc`, `engines`). См. раздел «Инструменты».
- **Шрифт:** Golos Text подключён из пакета `@fontsource-variable/golos-text` (`main.js`), админка не ходит за ним к Google. Название семейства в стилях — `"Golos Text Variable"` (`styles/tokens.css`, `styles/base.css`).
- **Страница сервера:** `window.ITK_ADMIN = { adminBase, apiBase, csrf, user, site:{name, domain}, mainLocale, siteTexts:{item, section}, locale, locales:[{code, name}], previewBase, loginUrl, logoutUrl, assetsBase, images:{uploadUrl, variantDir, widths}, theme }`. `locale` — язык интерфейса этого человека (на нём `t()`), `locales` — из чего он выбирает (каждый язык назван на себе), `mainLocale` — язык содержимого сайта, не интерфейса. `siteTexts` — заготовки названий нового элемента и секции на языке содержимого. `theme` — оформление (пункт «Оформление» ниже).
- **Превью картинок:** везде, где админка показывает картинку (`<img>` в полях, карточках, списках, ящике файла, редакторе текста), адрес идёт через `thumbUrl(src, ширина)` из `utils/media.js`: 320 (`THUMB`) для маленьких превью, 640 (`PREVIEW`) для карточек и ящика файла, 960 в тексте статьи. Помощник строит адрес WebP-копии по `window.ITK_ADMIN.images` (та же схема, что у `ImageVariants::url` на сервере); GIF, SVG, PDF, чужие адреса и режим `npm run dev` (схемы нет) остаются как есть. Сохранённые значения не меняются, меняется только показ. Новый `<img>` с картинкой из медиатеки пишите так же.

## Где что
- **Оформление:** цвета и скругления (тема) делает сервер (`Admin\Theme\AdminTheme`) и вставляет в оболочку как CSS-переменные до первой отрисовки; в стилях админки нет «зашитых» цветов бренда и акцента, только токены (`--cy*`, `--mag*`, `--brand-ink` для текста на цвете бренда, `--brand-text` для надписей брендовым цветом на светлом, `--rail-shade`; список в `styles/tokens.css`). `utils/theme.js` применяет ответ `/admin-theme` к открытой странице, экран — `components/settings/ThemePanel.vue` (+ `ThemeColor.vue`), клиент — `api/theme.js`. Новый стиль: цвет бренда или акцента пишите токеном; текст на фоне бренда — `var(--brand-ink)`, не `#fff`.
- `api/` — клиент: `http.js` (fetch, CSRF `X-CSRF-Token`, ошибки `{error, details}` → `ApiError`), по модулю на раздел (`pages`, `collections`, `requests`, `media`, `settings`, `users`, `site`, `proposals`). Над каждой функцией написан её endpoint.
- `schema/` — схема сайта. `registry.js` загружает `GET /admin/api/schema` в один объект `schema` до запуска приложения; остальные файлы — общая логика поверх него (шаблоны и правила размещения, правило H1, библиотека секций, настройки, области меню).
- `i18n/` — язык интерфейса, см. «Язык интерфейса». Это не язык содержимого.
- `stores/app.js` — сайт, языки, текущий пользователь и его права (`can(area, action, {template})`), счётчики в рельсе.
- `views/SettingsView.vue` + `components/settings/` — «Настройки сайта»: слева меню из шести разделов (`NAV` в `settingsSchema.js`: Основное, Меню, Переадресации, Уведомления, Пользователи и роли, Шаблоны), справа панель выбранного. «Основное» собирает все группы настроек схемы сайта на одной странице, по карточке на группу; права проверяются по карточкам. Старые адреса `/settings/<группа>` и `/settings/roles` открывают нужную карточку / вкладку.
- `components/editor/` — редактор страницы. Холст — `PreviewFrame.vue`: iframe `/admin/preview/{id}`, сервер рисует черновик шаблонами сайта; связь через `postMessage` (`itk:focus`, `itk:action`, `itk:select`, `itk:reload`, см. `packages/cms/public/preview.js`). После автосохранения iframe перезагружается с сохранением прокрутки.
- ИИ-предложения показываются только при `schema.features.ai`; языковой интерфейс скрывается, пока у сайта один язык.
- `layouts/AppLayout.vue` — рельса слева. Это данные: её строит **сервер** (`GET /admin/api/schema` → `nav`, ключ `app.nav` в `stores/app.js`): `[{ key, group, icon, order, items:[{ key, label, to, icon, order, badge?, sub? }] }]`, уже отсортировано и очищено до того, что человеку можно открыть. Группа с названием получает маленький заголовок, группа без названия («Сегодня», «Страницы», «Настройки») — просто список; `sub: true` — быстрая ссылка под предыдущим пунктом. Подсвечивается самый точный пункт для адреса (длиннее путь, больше ключей запроса). Число у пункта берётся из `app.badges[key]` (свежее), иначе из `badge` сервера. Новый класс раздела или `NavItem` расширения появляется в рельсе сам, в админке ничего про сайт не записано. Иконки — `components/ui/icons.js`; незнакомое имя рисуется значком документа.

## Список коллекции
Всё, что знает список, приходит из схемы коллекции (`cfg`); коды коллекций в нём не встречаются. Файлы: `components/collections/CollectionList.vue` + `list/` + `actions/`.
- **Данные.** `api.collections.query(col, { q, filter, sort, page, perPage })` → `{ items, total, page, perPage, facets, metrics }`: поиск, фильтры, сортировку и страницы делает база. Фильтр уходит как `filter[status]=…&filter[date][from]=…`, сортировка — `sort=-dateStart`.
- **Панель фильтров** (`list/ListFilters.vue`) рисуется по `field.filter = { kind, options }` каждого поля, у которого на сервере `filterable()`: `text`, `select`, `multi`, `toggle`, `dateRange`, `numberRange`, `relation`. Статус есть у каждой коллекции. Незнакомый вид отбрасывается. `facets` показывают, сколько записей с каждым значением.
- **Колонки и сортировка.** Название первым, дальше поля с `list.show === true` (или `null` у сортируемых); `hideOnIndex` на сервере → `list.show === false`. Клик по заголовку сортируемой колонки: нет → по возрастанию → по убыванию → нет. Тип значения в ячейке выбирает `list/CellValue.vue`.
- **Метрики** (`list/ListMetrics.vue`) — плитки над списком из `Metric::count/sum` ресурса.
- **Состояние** (`list/useListState.js`): фильтры, сортировка, размер страницы и вид запоминаются **на сервере** для человека (`api.prefs`, ключ `list.<коллекция>`, `GET/PUT /admin/api/prefs/{key}`) и возвращаются при следующем заходе с любого устройства. Поиск и номер страницы не запоминаются. Сохранённое, чего в схеме уже нет (поле убрали), отбрасывается при чтении (`sanitizeSaved`); если сервер всё же отказал (422), список открывается без фильтров.
- **Права на поля.** Поля, которые человеку нельзя видеть, сервер просто не присылает: клиент работает и когда поля нет (колонка не рисуется, у записи нет значения). `hideOnForm` → `form: false` (форма поле не рисует), `readonly` → `ro: true` (рисуется, но не правится).

## Дерево, календарь, доска
Три общих компонента, ни один не знает про конкретный сайт; логика отдельно от Vue там, где её можно проверить без браузера.
- **`components/ui/SortableTree.vue` + `treeOps.js`.** Дерево, узлы которого переносят: перетаскиванием за значок (`draggable` только у значка: в строках могут быть поля ввода) или с клавиатуры (Alt + ↑ ↓ → ←; те же действия в кнопках «Выше / Ниже / Вложить / Вынести»). Дерево вложенное: `[{ id, …, children: [...] }]` (`treeOps.nest(плоский список с parentId)` собирает его, `id-key`/`kids-key` переименовывают ключи). Пропсы: `max-depth` (уровней, с 1; узел считается со всей своей веткой), `can-drop({ node, parent, index, nodes })` → `true | false | 'причина'` (правило «куда можно», спрашивается после встроенных: не в себя, не в свою ветку, глубина), `locked(node)` (узел стоит на месте: главная страница), `tools` (кнопки в строке), `bare` (строка без своей рамки, у содержимого есть своя), `foldable`, `disabled`. Компонент ничего не меняет: событие `move({ id, node, parentId, index, from, to, nodes, groups })` отдаёт новое дерево родителю, тот сохраняет и возвращает дерево назад; `invalid(причина)` — перенос не разрешён. `treeOps.payload(nodes, groups)` собирает для сервера `[{ id, parentId, position }]` для «братьев» старого и нового родителя. Зона сброса на строке: верхняя треть — перед ней, нижняя — после (у раскрытой ветки — первым вложенным), середина — внутрь; куда нельзя, там красная рамка и причина под деревом. Живая строка для читалок экрана объясняет, где теперь узел. Применения: «Страницы» → «Изменить структуру» (`api.pages.tree`, правила размещения — `canPlace` из `schema/templates.js`, отмена переноса в уведомлении), пункты меню (`MenusEditor.vue`, глубина области), вид «Структура» коллекции с `tree()` (`api.collections.tree`).
- **`components/collections/list/CalendarView.vue` + `calendarModel.js`.** Месяц или неделя, неделя с понедельника, дни — строки `YYYY-MM-DD` (считаются в UTC, перевод часов никого не сдвигает). Пропсы `start`, `end` — ключи полей из настроек вида; событие `create(day)` (клик по дню или «+»), `move({ row, start, end, days })` (перетаскивание или Alt + стрелки: обе даты на то же число дней, время суток остаётся). Сохраняет `CollectionList.vue`: обычный `api.collections.update` черновика, строка меняется на экране сразу и возвращается, если сервер отказал; «вернуть» в уведомлении. В ячейке месяца три записи, дальше «ещё N» открывает неделю этого дня.
- **`components/ui/KanbanBoard.vue`.** Колонки по значениям (`columns: [{ value, label }]`, `column-of(item)`), карточка переносится перетаскиванием или кнопками «←» «→» (Alt + ← →); событие `move({ item, from, to })`, порядок внутри колонки не хранится. Слот `card`. Используется в списке коллекции (вид `kanban` из схемы: поле `select`) и на экране «Заявки» (вид «Доска»: Новая / В работе / Закрыта, статус меняет `api.requests.update`; спам на доске не показан).
- **Переключатель видов** над списком коллекции — `viewsOf(cfg)` из `list/listModel.js`: `table`, `cards`, `calendar`, `kanban` из `views` схемы, `tree` добавляется сам, если у коллекции `tree()`. Календарь, доска и дерево читают все записи сразу (`queryAll`: порциями по 200, до 2000), у них нет пейджера; выбранный вид хранится вместе с остальным состоянием списка (`api.prefs`). На экране «Заявки» вид хранится под ключом `requests.view`.

## Слова сайта берутся из схемы
В админке не записано название ни одного сайта и ни одного его предмета торговли. Что видит человек на экране, приходит со схемы (`schema/*`), общие слова лежат в `components/collections/labels.js` и `utils/format.js`.
- **Переключатель строки списка.** У коллекции — `cfg.toggleField` (ключ поля). Сервер отдаёт только его, поэтому название переключателя `toggleLabelOf(cfg)` из `labels.js` берёт подпись самого поля («На главной»); необязательное `cfg.toggleLabel` важнее подписи, но `Collection::toArray` его пока не шлёт. Поле без подписи называется «Показывать». Этим именем подписаны колонка и всплывающее сообщение после щелчка (`toggleNote()`): «Название»: «На главной» включится после публикации. У страниц переключатель «в списке родительской страницы» читает `listingSwitch(шаблон)` из `schema/templates.js`: поле, которое в `listing.onlyIf` называет шаблон родительской страницы со списком (`->listing(of: [...], onlyIf: 'show')`), подпись берётся у самого поля. Сайт без `onlyIf`, у страниц которого есть переключатель с ключом `catalog`, работает как раньше (запасной путь). Он же рисует колонку «плоского» списка (`PagesView.vue`) и предупреждение «Не показывается в списке» на карточке страницы (`TemplateCard.vue`).
- **Таблица опций** (`view: 'matrix'`, `components/collections/MatrixView.vue` + `matrixChanges.js`; слова — `schema/matrix.js`). Без настроек она говорит общими словами («столбец», «строка», «Новый столбец»). Свои слова задаются так: `cfg.newLabel` — только подпись кнопки добавления («Добавить тариф», это глагол, а не имя), `cfg.description` — строка под заголовком, `cfg.matrix.colFields[1].label` — название строки с ценой, `cfg.matrix.words = { colNew, colPlural: ['plan', 'plans', 'plans'], rowNew, … }` — любая фраза из `MATRIX_WORDS` (подстановка `{name}`); имя нового столбца («Новый тариф») задаётся только здесь, в `colNew`. Значение другого типа отбрасывается.
- **«Перенесена со старого сайта»** — подпись у страницы, пришедшей с сайта до CMS, пока её не правили (`MIGRATED_NOTE` в `utils/format.js`).

## История и корзина
`api/history.js` (`GET history/:kind/:id`, `history/revision/:id`, `POST history/revision/:id/restore`, `GET history/trash`) и `components/history/`: `HistoryDrawer.vue` — боковая панель «История» (список: кто, когда, что; запись открывается: что она изменила и что изменится, если её вернуть; «Вернуть эту версию» с подтверждением), `ChangeRows.vue` — строки изменений, `historyWords.js` — названия действий. Панель принимает `kind` (`page | item | settings | menu`), `resource-id`, `locale`, `can-restore` и сообщает `restored`; экран после этого заново читает черновик (редактор страницы — `ed.reloadDraft()`, запись — `load()`). Кнопка стоит в `EditorTopBar.vue` и в шапке `CollectionItemView.vue`; перед открытием экран досохраняет автосохранение. `views/TrashView.vue` (`/trash?kind=&key=`) — «Корзина»: удалённые страницы и записи, «Вернуть» открывает вернувшееся как черновик; ссылки на неё из «Страниц» и списка коллекции.

## Уведомления (колокольчик)
`api/notifications.js` (`GET notifications?unread=1&limit=&offset=`, `POST notifications/read { ids } | { all: true }`), `stores/notifications.js` (число непрочитанного, список панели, опрос раз в 60 секунд, пока вкладка открыта) и `components/notifications/NotificationBell.vue` — кнопка-колокольчик в углу блока сайта в рельсе (`layouts/AppLayout.vue`) со счётчиком и боковая панель «Уведомления»: «Все» / «Непрочитанные», «Отметить всё прочитанным», строка = заголовок, подробности, время. Клик по строке отмечает её прочитанной и ведёт по ссылке: маршрут админки (`/requests/12`) открывается через роутер, полный адрес — в новой вкладке. Что видит человек, решает сервер (по его правам и роли), клиент ничего не фильтрует.

## Действия
`Action::make(...)` в классе ресурса попадает в `cfg.actions` как `{ key, label, icon?, danger?, confirm?, modal?:{ title, fields }, places:['row','bulk','top','form'] }` (сервер уже убрал то, что человеку нельзя). `components/collections/actions/useActions.js`:
- места: `top` — кнопки в шапке списка; `bulk` — панель над таблицей, когда отмечены строки; `row` — меню строки («…»); `form` — меню «Действия» на странице записи (черновик сохраняется перед запуском);
- `confirm` → окно подтверждения; `modal` → окно с полями (`ActionDialog.vue` рисует их тем же `SchemaForm`, что и формы записей; обязательные проверяются до отправки);
- ответ `ActionResult`: `message` → всплывающее сообщение, `reload` → список перечитывается, `redirect` → адрес админки через роутер или внешний `http…` через браузер, `download` → файл скачивается; действие, которое само отдаёт файл, приходит как `{ file, blob, name }` и сохраняется. Отказ (422) показывается ошибкой, окно остаётся открытым.

## Плагины админки (`window.ITK`)
Пакет сайта подключает свой скрипт через `Registry::adminAssets(js: [...], css: [...])` на сервере. Оболочка объявляет заглушку `window.ITK = { plugins: [], registerPlugin }` **до** основного бандла и держит скрипты плагинов неактивными в `<template id="itk-plugins">`: админка сначала загружает язык и свой код, потом строит `window.ITK` (`plugins/registry.js` забирает то, что собрала заглушка) и запускает скрипты по порядку (`plugins/scripts.js`), так что плагин читает `ITK.vue` уже в первой строке; `plugins/state.js` хранит то, что плагины зарегистрировали (реестр реактивный: плагин, пришедший позже первого экрана, тоже подхватывается). **Первый экран ждёт скрипты плагинов:** `start.js` строит приложение, когда загружены и админка, и все скрипты плагинов (или они упали). Скрипт, который завис, задерживает первый экран до таймаута `WAIT` в `plugins/scripts.js`, сейчас 8000 мс; после этого админка стартует без него, а скрипт, пришедший позже, всё равно зарегистрируется (реестр живой). `registerPlugin` работает сразу. Сломанное описание пропускается, админку оно не ломает: плагин, который падает при отрисовке виджета, пропадает с экрана, остальное живёт.

**Версия контракта.** `ITK.version` — semver (сейчас `1.1.0`, константа `ITK_VERSION` в `plugins/state.js`). Минорная версия что-то добавляет, мажорная меняет или убирает то, на что плагин мог опираться. Плагин может сверить версию перед стартом: `if (!window.ITK || parseInt(ITK.version) !== 1) return`. Типы всего контракта: `admin/types/itk.d.ts`. Пакет админки приватный и в `node_modules` плагина не попадает: скопируйте файл в проект плагина (например, в `types/itk.d.ts`) и включите его в `include` у `tsconfig.json` / `jsconfig.json` либо добавьте `/// <reference path="../types/itk.d.ts" />` с относительным путём (к копии или к чекауту CMS). После этого глобальная `ITK` и `window.ITK` типизированы во всём проекте без импорта. Файл проверен `tsc` (TypeScript 5.9, `strict`, `moduleResolution: bundler`) на примере плагина с `registerPlugin`, `editorActions`, `actions`, `addRoute` и `ITK.version`.

```js
window.ITK.registerPlugin({
  // свой тип поля: поле схемы с t: 'color' рисует этот компонент (те же props и события, что у встроенных: ITK.ui.fieldProps / fieldEmits, components/form/fieldProps.js).
  // Необязательная функция cell(value, field) у компонента даёт текст для колонки списка.
  fields: { color: ColorField },
  // свой экран: пункт меню NavItem::make('Reports', '/x/reports') открывает #/x/reports этим компонентом (props: path, query)
  panels: { reports: ReportsPanel },
  // клиентская часть действия: 'ресурс:действие' или просто 'действие'. Функция получает { resource, action, ids, records, locale, run(input), done(result), toast, http }
  // и может вернуть ActionResult-подобный объект; { modal: Component } рисует компонент в окне (props: resource, action, ids, close(), run(input)).
  actions: { 'tours:export': async (ctx) => ctx.run({ format: 'csv' }) },
  // своя карточка записи на её странице (справа от формы): по ключу коллекции, props: cfg (схема коллекции), data (черновик). Без неё ядро рисует простую карточку:
  // картинка (thumbField), заголовок (titleField), строка (subField)
  previews: { tours: TourCard },
  // блок на экране «Сегодня», под секциями «Не опубликовано» и «ИИ-агент». Компонент рисует свою карточку (`.sheet`), props: locale.
  // Порядок блоков — порядок регистрации. Упавший при отрисовке виджет прячется, в консоли остаётся причина.
  widgets: { stats: StatsCard },
  // кнопка в шапке редактора страницы, после «Предпросмотр» (на телефоне — пункт меню «⋯»)
  editorActions: {
    check: {
      label: 'Check', icon: 'check', title: 'Check the page before publishing', order: 10,
      when: (ctx) => ctx.template === 'blog_article',          // необязательно: false прячет кнопку для этой страницы
      run: async (ctx) => { const r = await ctx.http.post(`x/check/${ctx.pageId}`); ctx.toast.show(r.ok ? 'All good' : r.message) },
    },
  },
})

// свой маршрут: #/reports/12. Путь начинается с «/», его первая часть не может совпадать с разделом админки
// (pages, collections, requests, media, settings, trash, health, x): такой маршрут отклоняется с объяснением в консоли.
// Ответ — функция, которая убирает маршрут (или null). meta.layout: 'app' (внутри рельсы, по умолчанию) | 'bare'; meta.title — заголовок вкладки.
const remove = window.ITK.addRoute({ path: '/reports/:id?', component: ReportPage, meta: { title: 'Report' } })
```

**Кнопка редактора** (`editorActions`): объект `{ label, run(ctx), icon?, title?, order?, when?(ctx) }`; без `label` или без `run` кнопка пропускается (в консоли причина). Перед запуском админка досохраняет автосохранение. `ctx`: `pageId`, `locale`, `title`, `status` (`published | draft | changed`), `template`, `readOnly`, `page` (копия черновика, читается по требованию), `flush()`, `reload()` (перечитать черновик после своих правок через `ctx.http`), `toast`, `http`. Ошибка из `run` показывается всплывающим сообщением.

**Маршрут** (`ITK.addRoute`): скрипт плагина приходит после бандла, а человек мог открыть `#/reports` раньше; роутер к этому моменту уже отправил его на «Сегодня» (адрес неизвестен). Когда маршрут появляется, такого человека переводят туда, куда он шёл. Если меню — всё, что нужно, проще `panels` и `NavItem::make('Reports', '/x/reports')`. Маршрут отклоняется (в консоли причина, `addRoute` отвечает `null`), если путь начинается с раздела админки, если у `component` опция `template` без `render` (экран был бы пустым) или если `name` совпадает с именем маршрута ядра (`today`, `pages`...): иначе vue-router заменил бы маршрут админки.

### Что доступно плагину
- `ITK.version` — версия контракта.
- `ITK.vue` — **весь Vue** (`import * as Vue`): `h`, `ref`, `reactive`, `computed`, `watch`, `defineComponent`, и всё, что импортируют собранные `.vue` (`openBlock`, `createElementBlock`, `createVNode`, `toDisplayString`, `withCtx`, `normalizeClass`…). Это тот же Vue, что у админки, реактивность общая.
- `ITK.http` — клиент API с CSRF (`get / post / put / patch / del / upload`), `ITK.toast` (`show`, `error`), `ITK.confirm({ title, message, confirmLabel, danger })` → `Promise<boolean>`, `ITK.addRoute`.
- `ITK.i18n` — язык интерфейса: `t(key, params)`, `locale`, `add(locale, messages)` для текстов самого плагина (`add('ru', { 'reports.title': 'Отчёты' })` (английский текст плагин добавляет так же, `add('en', { 'reports.title': 'Reports' })`); форма числа — объект `{ one, few, many, other }`). Страница перезагружается при смене языка, реактивность не нужна. Скрипты плагинов запускаются после загрузки языка и кода админки, поэтому `ITK` готов с первой строки плагина. По той же причине `add` может заменить ключ админки только для вызовов `t()` после старта: константы модулей (меню, схемы) уже вычислены.
- `ITK.ui` — готовые части админки (props и события смотрите в файле компонента, `components/ui/` и `components/form/`):

  | Имя | Что это |
  |---|---|
  | `Modal`, `Drawer`, `Popover` | окно по центру (`v-model:open`, `title`, слот `footer`), правая панель, меню у кнопки (`anchor`, `align`) |
  | `ConfirmDialog` | окно, которое открывает `ITK.confirm()`. Оно уже один раз стоит на странице, своё рисовать не нужно: вызывайте `ITK.confirm()` |
  | `SchemaForm` | форма по описанию полей (`schema`, `v-model`, `published`, `readonly`), как формы записей и действий |
  | `FieldShell`, `FieldRenderer` | обёртка поля (подпись, подсказка, ошибка) и выбор компонента по `field.t`, в том числе вашего |
  | `TextField`, `TextareaField`, `HeadlineField`, `NumberField`, `ToggleField`, `SelectField`, `ImageField`, `LinkField` | базовые поля |
  | `fieldProps`, `fieldEmits` | props и события, которые принимает компонент поля |
  | `Icon`, `SortableTree`, `KanbanBoard` | значок по имени (`components/ui/icons.js`), дерево и доска с переносом |

- Классы из `styles/base.css`, они уже на странице, подключать ничего не нужно: `.page` (страница в рельсе: `max-width`, поля) с `.page-h` (шапка: `h1`, `.sub`, `.actions`), `.sheet` (белая карточка), `.btn` (+ `primary`, `ghost`, `danger`, `sm`, `icon`), `.alert` (+ `info-a`, `warn-a`, `err-a`), `.chip`, `.muted`, `.sr` (только для читалок экрана). Цвета и отступы берите токенами (`var(--ink)`, `var(--cy)`, `var(--hair)`…, `styles/tokens.css`), не числами: тема сайта меняет их.

### Как собрать плагин из `.vue`
Описание на `h()` работает без сборки. Свои `.vue` собирает Vite, `vue` остаётся **внешним** и берётся из `ITK.vue`. Скрипт грузится как `type="module"`, формат — `iife`:

```js
// vite.config.js плагина
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [vue()],
  define: { 'process.env.NODE_ENV': '"production"' }, // в режиме lib Vite его не подставляет
  build: {
    lib: { entry: 'src/plugin.js', name: 'MyPlugin', formats: ['iife'], fileName: () => 'admin.js', cssFileName: 'admin' }, // стили из <style> уйдут в admin.css рядом (без cssFileName файл назвали бы по имени пакета): Registry::adminAssets(css: [...])
    rollupOptions: { external: ['vue'], output: { globals: { vue: 'ITK.vue' } } },
  },
})
```
`src/plugin.js` вызывает `window.ITK.registerPlugin({...})`. Не кладите Vue в бандл плагина: второй экземпляр Vue ломает реактивность и `provide / inject`.

**Опция `template:` без сборки не работает.** В админке Vue без компилятора шаблонов, компонент `{ template: '<b>x</b>' }` ничего не нарисует, а Vue в продакшене молчит. Админка теперь сама предупреждает в консоли (и в разработке, и в продакшене): «Компонент «имя» (вид) плагина описан через опцию template…», и такой компонент не регистрируется. Лекарство: `render()` на `h()` из `ITK.vue` или сборка `.vue`, как выше.

## Язык интерфейса
`i18n/index.js`: `import { t, locale, formatDate, formatNumber, collator } from '@/i18n/index.js'`. Тексты лежат в `i18n/<locale>/<area>.json`, ключи плоские: `"area.key"`, после точки snake_case. Параметры `{name}`: `t('area.key', { name: x })`. Множественное: `t('area.key', { count: n })`, в JSON объект по категориям `Intl.PluralRules`: `{"one":…,"few":…,"many":…,"other":…}` для ru, `{"one":…,"other":…}` для en, `{"other":…}` для kk. Нет ключа в языке: берётся английский текст, нет и его: сам ключ и `console.warn` в разработке. Даты, числа и сортировка идут через `formatDate`, `formatNumber`, `collator`. Ограничение: в части сборок Chrome (проверено на 152 и 156) нет данных Intl для `kk`, хотя `supportedLocalesOf` отвечает, что язык есть, и даты выглядели бы как «M11 2, Mon». `initI18n` проверяет это (`hasIntlData`); если данных нет, на казахском даты числовые (`02.11.2026`, названия месяцев и дней отбрасываются, кроме заголовка дня недели отдельно), а числа и сортировка идут через `ru` (тот же знак дробной части и пробел-разделитель). Полифил не подключается, массивы месяцев не хранятся.

`main.js` сначала загружает чанк языка (и английский за ним), потом динамически импортирует `start.js` со всем приложением, поэтому `t()` работает и на верхнем уровне модуля. Смена языка перезагружает страницу, так что реактивность не нужна. Даты, числа и сортировка идут через `formatDate`, `formatNumber`, `collator` (`list.sort(collator.compare)` или `collator({ numeric: true }).compare`), а не через `'ru-RU'` и `localeCompare`.

`formatDate` на пустой дате (`null`, `undefined`, `''`) и неверной дате возвращает пустую строку, а не бросает ошибку.

Холст редактора (`packages/cms/public/preview.js`) работает внутри страницы сайта, каталога у него нет, а маршрут `itk_admin_preview` намеренно не переключается на язык человека: страница рисуется на своём языке, как её увидит посетитель. Слова панели над секцией приходят в `window.ITK_PREVIEW.texts`: `PreviewController::texts()` собирает их внутри `AdminLocale::runFor($user, …)` из `translations/itk_preview.<locale>.yaml`, скрипт читает через `say(name, label)`. Новое слово добавляется в каталог и в `texts()`, кириллицу в `preview.js` проверяет `check:i18n`.

Язык приходит в `window.ITK_ADMIN.locale`, выбор человека сохраняет `setLocale(code)` (`PUT me/locale`, окно «Мой профиль»). В `npm run dev` и `npm run dev:mock` оболочки нет: язык хранится в `localStorage`, по умолчанию английский.

`npm run check:i18n` (`scripts/check-i18n.mjs`) проверяет каталоги админки и бандла: паритет ключей и параметров, формы числа (если они есть у ключа в одном языке, то нужны во всех), ключи из `t()`, `I18n::t()` и `itk_t()`, неиспользуемые ключи и кириллицу вне комментариев. Скрипт в `package.json` запускается с `--strict`: неиспользуемый ключ (предупреждение) тогда тоже ошибка, и CI вызывает его шагом `npm run check:i18n`. `--area=<имя>` проверяет одну область, `--warn-cyrillic=<путь>` только перечисляет кириллицу под путём. Ключ, собранный из кусков, виден по литеральной части; иначе нужен комментарий `i18n-dynamic: area.prefix_`. Кириллица, которой место в коде: комментарий `i18n-ignore` в строке или запись в `scripts/check-i18n.allow.json`.

## Разработка без оболочки сервера
`npm run dev` не получает от сервера `window.ITK_ADMIN` (там лежат адреса админки, CSRF-токен, пользователь, тема), поэтому `api/http.js` берёт запасные значения: `/admin` (или `VITE_ITK_ADMIN_PATH`) и токен из ответа `GET /me` (`api/users.js` отдаёт `csrf` в `setCsrf`). **Запись из `npm run dev` работает, потому что сервер кладёт `csrf` в ответ `GET /me`** (`MetaController::me()`, тот же токен, что в `window.ITK_ADMIN.csrf`; отдаётся только вошедшему, чужой получает отказ без токена). Если сайт подключает более старый бандл без этого ключа, первая же запись (автосохранение, переключатель) получает 403 `{ details: { code: 'csrf' } }`; клиент тогда не показывает «Страница устарела», а объясняет причину (`DEV_CSRF_HINT` в `api/http.js`).
Токен тот же, что оболочка кладёт в `window.ITK_ADMIN.csrf` (HMAC пользователя и сессии), его видит только человек со своей сессией.

## Режим VITE_MOCK
`npm run dev:mock` (то же, что `VITE_MOCK=1 npm run dev`; файл `.env.mock` включает его для `vite --mode mock`) показывает экраны без PHP и без базы. `main.js` вызывает `mock/install.js`, который подменяет `fetch` для адресов `/admin/api/*`: ответ даёт `mock/handler.js` из данных `mock/fixtures.js` (выдуманный сайт «Демо-сайт»: схема с секциями и шаблонами, 8 страниц, коллекция «Новости», таблица «Тарифы»). Запись идёт в память вкладки (черновик, публикация, отмена правок, создание, удаление, перенос в дереве), перезагрузка страницы возвращает фикстуры. Предпросмотр страницы — заглушка (его в обычном режиме рисуют шаблоны сайта). Чего в моке нет (заявки, медиатека, настройки, пользователи), в меню не видно: у роли «Администратор» из фикстуры нет прав на эти области, поэтому ссылка на такой экран (`#/requests`, `#/media`, `#/settings`) показывает «Нет доступа», а запрос до мока не доходит. Если дать роли права на область в `fixtures.js` (`perms`), экран откроется и обратится к API: мок ответит на этот запрос 404 «Этого в демо-режиме нет». В сборку (`npm run build`) мок не попадает: ветка в `main.js` вырезается, пока переменной нет. Обработчик — чистый код, у него есть тесты (`mock/handler.test.js`); новый экран, которому нужен ответ, добавляется в `handler.js` и `fixtures.js`.

## Инструменты
- **Node 18.18+** (`.nvmrc`, `engines`), `npm ci`. Лицензия пакета MIT, поле `repository` указывает на каталог `admin`.
- **Lint:** `npm run lint` — ESLint 9 (плоский конфиг `eslint.config.js`) с `eslint-plugin-vue` (набор `essential`) и `@eslint/js`: только ошибки, без правил оформления. Prettier нет: оформление как в окружающем коде.
- **Тесты:** `npm test` — Vitest 3, окружение `node`, без DOM. Покрыта чистая логика: `treeOps`, `calendarModel`, `format` (даты, числа, адрес сайта), `plural` и объекты, адреса страниц (`slug.js`), адреса картинок (`media.js`), слова таблицы опций и её изменения, переключатель списка, HTTP-клиент, реестр плагинов и маршруты, мок-сервер. Рядом с файлом лежит `*.test.js`. Vitest 3 остаётся из-за Node 18: `npm audit` помечает как critical сам `vitest` и транзитивные `tinypool` и `@vitest/mocker`, исправления есть только в Vitest 4.1.12+, а он требует Node 20+. Это только dev-цепочка, в сборку не попадает. Остальные находки `npm audit` тоже из dev-цепочки (ESLint и `minimatch`), кроме одной: `npm audit --omit=dev` показывает moderate у Tiptap 2.27.3 (`mergeAttributes`, GHSA-cp6q-959q-f8rh). Tiptap попадает в сборку, исправление только в мажорной версии 3, поэтому переход на неё — отдельная задача.
- **Сборка:** `npm run build` (Vite 6.4) кладёт админку в `packages/cms/public/admin`. Проверить, не трогая каталог пакета: `npx vite build --outDir /tmp/itk-admin-check --emptyOutDir`. Tiptap и ProseMirror вынесены в отдельный именованный чанк `tiptap` (`manualChunks` в `vite.config.js`) и не грузятся на экранах без редактора: `TextareaField` и `HeadlineField` берут его через обёртку `form/RichTextAsync.js`. Экраны, которые ставят фокус в такие поля (редактор страницы и запись коллекции), получают чанк вместе с маршрутом (`withRichText` в `router/index.js`), поэтому поле рисуется с редактором сразу и первый щелчок по тексту на холсте попадает в него. На остальных экранах чанк грузится при первом поле с rich text. Vue лежит в своём чанке `vue`: иначе Rollup кладёт рантайм туда, откуда его достаёт чанк Tiptap, и редактор тянется на каждый экран. Не импортируйте `RichText.vue` напрямую из кода, который идёт в основной бандл. Проверка: в `index.html` сборки нет `modulepreload` на `tiptap`, в `.vite/manifest.json` у `index.html` в `imports` только `vue`, в чанке `tiptap` нет рантайма Vue. Предупреждение о размере чанка (`chunkSizeWarningLimit`) оставлено на 900 кБ.
