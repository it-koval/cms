# Журнал изменений

Все заметные изменения ITK CMS записываются в этот файл. Формат следует [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии следуют [семантическому версионированию](https://semver.org/lang/ru/spec/v2.0.0.html). Поддерживаемые точки интеграции перечислены в [публичном API](packages/cms/API.ru.md).

## [0.3.0] - 2026-11-25

### Несовместимые изменения

- Функции Twig `menu`, `settings`, `listing`, `media_url`, `media_srcset`, `media_width`, `media_ratio`, `page_url` и `render_sections` получили префикс `itk_`. См. [команду замены](UPGRADE.ru.md#функции-twig).
- Списки заявок и медиа в админке принимают `page` и `perPage` и возвращают объект с пагинацией. Соседние страницы в админке и MCP доступны по курсору на основе даты создания и ID. См. [UPGRADE.ru.md](UPGRADE.ru.md#030).
- У полей формы без `max()` предел 1000 символов. Такие поля показывают проверка схемы и «Состояние сайта». MCP `request_get` читает до 6000 символов каждого значения формы.
- Шаблоны страниц дают доступ Автору через `forAuthors()`. Для просмотра использования медиа нужен `Viewer`. Кастомные поля могут разрешить извлечение в базу знаний через `PublicFieldInterface`.
- Чтение singleton-коллекции возвращает начальные значения до первого сохранения. Линтер схемы отклоняет поля коллекций с зарезервированными ключами.
- `GET /admin/api/collections/{col}` всегда возвращает объект с пагинацией `{ items, total, page, perPage, facets, metrics }`. Поиск, фильтры, статус и отбор переводов действуют до подсчёта и пагинации. Опубликованные версии с правками входят в фильтр `draft`. Клиенты должны читать `items` и запрашивать следующие страницы. См. [UPGRADE.ru.md](UPGRADE.ru.md#030).
- `Mcp\AbstractMcpTool::locale()` теперь нестатический. Внутри методов экземпляра работают `self::locale($args)` и `$this->locale($args)`. Вызовы из статического контекста больше не поддерживаются. См. [UPGRADE.ru.md](UPGRADE.ru.md#030).
- Группы настроек сайта не могут использовать ключи ядра `menus`, `redirects`, `seo`, `notifications`, `mail`, `bots`, `theme`, `languages`, `users`, `mcp` и `seo-files`. Переименуйте группы и обновите права `set:<group>` и ссылки видимости полей, сохранив ключи полей. См. [UPGRADE](UPGRADE.ru.md#зарезервированные-группы-настроек).
- Публичные формы принимают JSON как плоский объект до 1000 скалярных значений или `null`. Массивы и вложенные объекты дают HTTP 422. Приём заявок управляется системной настройкой уведомлений `itk:forms`. Поле сайта `forms` сохраняет собственное значение.
- Редактор «Фото» добавляет объекты `{src, alt}`. Старые URL-строки остаются допустимыми. До добавления новых фото шаблоны сайта должны поддерживать оба формата. См. [UPGRADE](UPGRADE.ru.md#другие-изменения).
- Удалены панель предложений ИИ в редакторе и опция схемы `feature('ai')`. Обновите схему сайта по [UPGRADE.ru.md](UPGRADE.ru.md#предложения-ии).
- Из `itk:make:collection` удалены перенос строк в записи и опции `--import` и `--publish`. Команда игнорирует поле `rows` в JSON и по-прежнему создаёт класс по таблице или описанию. Переносите записи старого сайта своим скриптом вместе с дампом базы. См. [UPGRADE](UPGRADE.ru.md#импорт-строк-в-коллекции).
- Миграции базы 0.3.0 несовместимы с 0.2.2 и частично необратимы. Для отката нужны база и загрузки до обновления вместе с соответствующим исходным развёртыванием. См. [UPGRADE](UPGRADE.ru.md#откат-на-022).
- Старые ссылки восстановления и приглашения истекают. Задайте `itk_cms.public_url`, удалите прежние задания писем со ссылками и запросите новые. Для нового повтора уведомления интеграции используют `RequestQueue::enqueue(..., resend: true)` вместо прямой отправки прежнего `SendRequestNotification`. См. [UPGRADE](UPGRADE.ru.md#другие-изменения).

### Добавлено

- Через `make` можно запустить стенд разработки и локально выполнить проверки CI (`make help`). По умолчанию стенд использует порты 18020–18023 на `127.0.0.1`. См. [CONTRIBUTING](CONTRIBUTING.ru.md).
- `itk:requests:recover` запускает восстановление заданий и событий доставки заявок. После проверки чата Telegram/MAX команда `itk:requests:resolve <request> <telegram|max> <recipient> <sent|rejected>` фиксирует результат. `itk:requests:resend <request> --channel=<telegram|max>` продолжает доставку. Для SMTP используйте `itk:requests:mail:resolve <request> <recipient> <sent|rejected>`, а после подтверждённого отказа — `itk:requests:resend <request> --channel=mail --recipient=<address>`. Команды восстановления почты работают без транспорта ошибок. При наличии соответствующего задания команда разрешения также печатает его команду повтора.
- Добавлены кодекс поведения, шаблоны задач и pull request, руководство по выкладке и откату и production-файл Compose. См. [DEPLOY.ru.md](docs/DEPLOY.ru.md).
- «Состояние сайта» и `itk:doctor` сообщают о нечитаемых ключах двухэтапного входа и используют одну проверку GD/WebP.
- `itk_cms.analytics.start` задаёт `auto` (по умолчанию) или `manual` в конфигурации сайта. Браузерный API `window.itkAnalytics.start()` запускает все настроенные счётчики, `start(['ga'])` выбирает GA. Ключи счётчиков — `metrika` и `ga`. Новые запуски отправляют на `document` всплывающее событие `itk-analytics:started` с `detail.counters`. Повтор без новых счётчиков не создаёт событие.
- В списках страниц и записей виден статус перевода. Нажатие на язык открывает нужную версию. Переключатель языка есть в редакторах, переводимых настройках и меню. Экран «Сегодня» и счётчики коллекций учитывают все настроенные языки.
- История страниц и записей показывает изменения по одному языку или по всем сразу. `GET /admin/api/history/{kind}/{id}?scope=all` использует общую пагинацию. Восстановление обновляет черновик языка выбранной версии.
- `itk_cms.requests.max_body` задаёт предел тела публичной формы в байтах. `itk:install --password-file` читает пароль первого администратора из подключённого файла секрета.
- Тип секции может объявить первый экран через `firstScreen()`. Свои типы полей могут реализовать `ValueValidatingFieldInterface`.
- Многоязычное SEO выводит взаимные `hreflang` и добавляет `x-default` для индексируемой основной версии. Опубликованная страница подставляет собственный URL, если canonical пуст. Карта сайта включает индексируемые версии всех языков, а `llms.txt` группирует страницы по языкам. Оба файла обновляются после фиксации изменений и перепроверяются по ETag содержимого.
- `itk:doctor` проверяет префиксы языков, главные страницы, пустые настройки и меню, а также ручные файлы для поисковых роботов.
- Публичные маршруты отдают опубликованные версии по адресам вроде `/kk/about`.
- В Twig доступны поля `html_lang`, `og_locale` и `translations`. В `translations` перечислены опубликованные версии для переключателя языков.
- `RecordTranslationAdded` и `RecordTranslationRemoved` наследуют `RecordEvent`, передают язык операции и отправляются после commit. Операции с переводами не вызывают события создания/удаления объекта и хуки жизненного цикла; при удалении опубликованного перевода сохраняются события и хуки снятия с публикации.
- Переводы страниц и записей коллекций можно создавать и удалять через JSON API админки и публичные методы `PageService` и `CollectionService`. Новый перевод становится черновиком: копией версии на другом языке или значениями из схемы. Удаление сохраняет остальные языки. Основную и последнюю версии удалить нельзя.
- `itk_cms.locales` задаёт языки содержимого, их названия и метаданные.
- Публичный сервис `Itk\Cms\I18n\ContentLocales` отдаёт упорядоченный список языков, названия, префиксы и метаданные.

### Изменено

- Поддерживаемые PHP-типы перечислены в [публичном API](packages/cms/API.ru.md). Внутренние типы и методы реализации `PageService` помечены `@internal`.

- After-события записей передают снимок в `data.fields`, `data.meta` и `data.status`. При публикации передаётся опубликованная версия, при удалении передаётся снимок до удаления.
- CI запускает матрицу PHP и Symfony в Docker, проверяет PostgreSQL 16 и 17 и минимальные зависимости, два случайных порядка тестов, чистую установку Symfony и production-стек Compose. Публикация split-пакета требует успешного CI на том же коммите.
- Архив Composer больше не включает скрипты разработки.
- «Сегодня» читает версии батчами и показывает восемь последних новых заявок со ссылкой на весь список. Публичные списки читают нужную ветку страниц и опубликованные записи коллекций. Команда прогрева медиа читает файлы батчами и использует общий генератор копий.

- Аналитика инициализируется одним версионированным внешним загрузчиком с `defer` и атрибутами `data-*`. В `manual` бандл не делает запросов и предварительных соединений с провайдерами до `start()` и не выводит пиксель `<noscript>` Метрики. В `auto` пиксель сохранён. Метатеги подтверждения доступны в обоих режимах. Сайт управляет согласием, его хранением и перезагрузкой после отзыва, а перед переходом на `manual` убирает собственные прямые вставки аналитики. См. [UPGRADE.ru.md](UPGRADE.ru.md#030).
- Штатный транспорт `async` повторяет доставку заявки через 60, 120 и 240 секунд. Ручная отправка более 20 частей для одного канала идёт в очередь, админка подтверждает постановку.
- Админка и предпросмотр используют базовый путь и CDN из Symfony Asset. Версия и манифест сайта применяются к его собственным файлам. Стандартные переопределения Twig имеют приоритет.
- Интеграции админки могут менять параметры доставки через `settings?scope=notifications`. Параметры хранятся отдельно от одноимённых полей сайта.
- Консоль и воркеры используют язык приложения. Админка и адресные письма сохраняют свой язык.
- Домен проверяется при сохранении.
- IndexNow отправляет затронутые адреса всех включённых языков. Критический CSS строится для опубликованных версий этих языков.
- Публикация или снятие перевода обновляет кэш HTML и ETag других версий той же страницы.
- На сайтах со списком языков публичные страницы и предпросмотр переводят шаблоны на язык страницы. JSON-LD использует её тег языка HTML.
- На сайтах со списком языков формы сохраняют язык из `?locale=`, из `Referer` того же сайта или из настройки основного языка. Сообщения формы, включая `429`, используют язык заявки, если в бандле есть перевод. Устаревший или неподдерживаемый `?locale=` сохраняет корректную заявку на основном языке и оставляет предупреждение в журнале.
- На сайтах без `itk_cms.locales` сообщения формы используют основной язык сайта, если в бандле есть перевод. Раньше язык сообщений определялся через `admin_locales`.
- MCP вызывает хуки загрузки один раз для каждого ресурса и языка в каждом запросе.
- API админки проверяет язык по общему правилу и возвращает `422` для кода вне явно заданного списка.
- На сайтах с несколькими языками версии страниц используют префиксы своих языков. Адрес основного языка не может занимать первый сегмент другого настроенного языка.
- PHP и редактор админки используют общую таблицу транслитерации русских и казахских букв при генерации адресов.
- Повторная публикация по тому же адресу ставит в очередь одно уведомление IndexNow.

### Исправлено

- Предпросмотр открывает поле по клику на текст внутри раскрывающегося блока, а также поля размеченных записей коллекций и настроек на языке предпросмотра. У каждого фото свой редактируемый alt-текст.
- Введённое сохраняется при отказе удаления или отмене ухода. Esc закрывает верхнее окно, опасное подтверждение ставит фокус на «Отмена», а профиль предупреждает перед закрытием с правками.
- Списки коллекций показывают ошибку с повтором и блокируют перенос в дереве, если отсутствует родитель. Ошибки полей связаны с полями ввода. Названия файлов и форм переносятся на узких экранах.
- Сохранение черновика страницы сохраняет кеш карты сайта.

- Переключатель языков, файлы для роботов, IndexNow и критический CSS учитывают только версии, которые открываются по адресу своего языка. При переносе версии другие страницы по её прежнему адресу продолжают открываться.
- Публичные страницы и маршруты для роботов продолжают работать при неверном публичном адресе. Doctor сообщает об ошибке настройки.
- Генерируемые canonical и `hreflang`, проверка адреса SEO, карта сайта, файлы для роботов, JSON-LD и IndexNow используют нормализованный `itk_cms.public_url`, а при его отсутствии или ошибке берут настроенный `domain`. Адрес SEO не зависит от хоста, схемы и порта запроса. Без настройки адреса сайта абсолютные SEO-ссылки не генерируются.
- ETag и кеш HTML одноязычных страниц меняются при изменении настроенного адреса SEO. Карта сайта с одной настройкой `domain` нормализует IDN, регистр хоста и стандартные порты при любом числе языков.
- Миграция настроек копирует эффективные значения, которые читала 0.2.2, в `itk:` без удаления и переименования исходных строк. Существующие внутренние значения имеют приоритет. Флаги сохраняют логический смысл, маршруты — числовые ключи форм, включая `"0"`. API уведомлений возвращает маршруты JSON-объектами. Настройки SMTP отделены от полей сайта с именем `mail`.
- Пути SEO-правил нормализуют процентное кодирование, сохраняя экранированные разделители `%2F`, `%3F` и `%23`. Миграция `20261124120100` обновляет старые правила и оставляет конфликтующие без изменений, выводя их ID для проверки оператором до открытия трафика.
- Канонический редирект слеша сохраняет исходную строку запроса, включая повторяющиеся параметры. SEO-проверка следует тому же маршруту и показывает canonical и правила языка адреса.
- «Состояние сайта» перечисляет поля формы без явного предела. Статусы длинных повторов сохраняются по каналам при обновлении карточки. После исчерпания попыток канал снова доступен для повтора.
- Некорректный JSON публичной формы возвращает ошибку проверки. Слишком большое тело возвращает HTTP 413 до разбора.
- Если в старых настройках SMTP сохранён пароль без шифрования, админка сообщает, как восстановить доставку.
- Хуки повторной публикации получают опубликованный снимок. При правке страниц действуют общие проверки заголовка и адреса. SEO-поля очищаются одинаково. Циклы обнаруживаются на любой глубине, массовое удаление начинает с потомков.
- Telegram и MAX сохраняют принятые части по получателям и используют сохранённый текст при повторе незавершённой операции, в том числе после выключения и включения канала. Часть в состоянии `sending` ждёт решения оператора. Повтор пропускает принятые части и может отправить части с подтверждённым отказом. Ручной повтор после полного отказа запускает новую операцию с новым текстом.
- Результат доставки Telegram определяется по исходному POST. Ответ 2xx подтверждает приём только при наличии `ok: true` и `result.message_id`. HTTP 4xx, кроме 408, и подтверждённый сбой до отправки считаются определённым отказом. Ответ 2xx без подтверждения, 408, 5xx и потеря ответа после отправки оставляют исход неопределённым. Поздняя ошибка слушателя не меняет исход POST. Несовместимый декоратор HTTP-клиента даёт определённый отказ до отправки.
- SMTP-письма о заявках сохраняют принятие по получателям. Неопределённый получатель блокируется до решения оператора. Старое общее предупреждение о почте остаётся открытым: 0.2.2 не сохраняла полный исторический список получателей. После проверки всех исторических адресатов оператор может явно закрыть его через `itk:requests:mail:resolve <request> --legacy-checked`. Адресатов сверяют по историческим данным об отправке.
- Для писем о заявках составной SMTP-транспорт переходит к другому серверу только после подтверждённого отказа. Потеря подтверждения останавливает отправку и сохраняет неопределённый результат.
- Короткий повтор и запись отказа очереди для зафиксированной заявки используют одно сериализованное соединение для резерва и итога, не блокируясь на собственном резерве в транзакции вызывающего кода. Штатный `messenger:failed:retry` открывает актуальное неудачное задание, сохраняя завершённые и заменённые закрытыми. Работающий воркер удерживает блокировку доставки после истечения аренды.
- Намерение поставить уведомление в очередь фиксируется в PostgreSQL вместе с заявкой. Работающий воркер Messenger восстанавливает непереданные задания с исходными ID.
- Итог доставки сохраняет ожидающее событие до успешной обработки слушателями. Воркер и `itk:requests:recover` повторяют событие без отправки сообщения провайдеру. Собственные слушатели должны быть идемпотентными.
- Итог доставки фиксируется в базе перед вызовом слушателей события. Попытки отправки одной заявки в один канал выполняются последовательно. База данных устраняет дубли уведомлений. Старые записи истории удаляются вместе с сохранением новой ревизии.
- Некорректные даты заявок и слишком длинные адреса переадресаций дают ошибку валидации. Переадресация может учитывать параметры запроса. Разбор критических стилей сохраняет строки и экранирование CSS.
- MCP stdio и воркеры сбрасывают состояние между сообщениями. Ошибка создания инструмента MCP попадает в журнал. Остальные инструменты доступны. Обработчики Messenger работают с именованными шинами.
- Команды и диагностика согласованно проверяют каталог загрузок, имена транспортов с точкой, ключи полей и встроенные типы. Имя колонки даты создания страницы задано явно.
- База знаний повторяет временно неудачные задания, учитывает изменение `noindex` и указывает фактические ключи полей в найденных фрагментах.

### Безопасность

- `itk:schema:lint` предупреждает о `canSee()` и `readonly()` во вложенных полях и указывает, какие поля вынести на верхний уровень.
- История настроек фильтрует вложенные поля перед построением описаний и сохраняет текущие защищённые значения при восстановлении. Новые ревизии явно различают настройки сайта и внутренние уведомления. Старые ревизии уведомлений без такого признака доступны только полному администратору и только для чтения. История удалённых групп доступна полному администратору только для чтения.
- Ссылки восстановления используют заданный адрес и погашаются под блокировкой базы. Docker-кит применяет nginx-предел тела `256k` только на `/request/{form}`. Для загрузки медиа сохранён предел nginx `256m`. Production-службы PHP и воркера подключают seccomp-профиль Chromium на основе Docker Engine 27.5.1, в том числе при выключенной сборке критического CSS.
- Действия коллекций требуют входа и разрешения. Блокировка пользователя закрывает следующий запрос его сессии. Ошибки входа показывают одинаковый текст. Двухэтапный вход сериализует проверку и ограничивает попытки на пользователя.
- В очередь попадают задания доставки. После каждой неудачной отправки воркер отзывает её ссылку.
- Для сохранённых паролей SMTP требуется TLS. «Состояние сайта» и `itk:doctor` предупреждают о паролях в `MAILER_DSN` с необязательным TLS. Чувствительные параметры и ошибки транспорта скрывают учётные данные. Установщик проверяет длину пароля от 10 до 200 символов, в том числе при чтении из подключённого файла.
- PHP и редактор отклоняют управляющие символы в URL внутри HTML. Критический CSS запускает Chrome с песочницей и ограничивает соединения локальным сервером рендера. Размер кэша поисковых векторов ограничен.
- Сервис токенов отклоняет неизвестные права.
- Редактор и сервер одинаково очищают адреса в форматированном тексте. При переданном CSP nonce стили применяются без обработчика события в HTML.

## [0.2.2] - 2026-11-22

### Исправлено

- Значение формы больше не теряет текст после `<`. Раньше `<500`, `<XS` или `2<3` обрезали значение до следующего `>` или до конца, и заказ мог потерять конец списка с итогом. HTML-теги по-прежнему удаляются: имя элемента строчными буквами с атрибутами вида `name="value"`. Любой другой `<` остаётся текстом, после него ставится пробел (`<500` сохраняется как `< 500`). Пробел входит в `max()`, а `pattern()` теперь видит текст, который раньше пропадал.

## [0.2.1] - 2026-11-22

### Исправлено

- Поле формы с `max()` больше 1000 больше не теряет текст после 1001 символа. Значение в пределах `max()` сохраняется целиком (как и раньше, после обрезки пробелов по краям и удаления тегов), `pattern()` проверяет его целиком. Более длинное получает штатную ошибку «поле длиннее», заявка не создаётся. Поле без `max()` по-прежнему оставляет первые 1001 символ без ошибки.
- Заявка, которая не влезает в одно сообщение Telegram или MAX, уходит несколькими сообщениями по порядку, с паузой от секунды из-за лимитов частоты мессенджеров. Раньше Telegram её отклонял, а MAX обрезал на 4000 символов. Заявка считается доставленной, когда ушли все сообщения. Повтор начинается с первого, поэтому часть сообщений может прийти в чат дважды.
- Карточка заявки показывает имя, город и телефон целиком, если они длиннее своих колонок в базе (120, 120 и 32 символа). В списке остаются короткие значения.

После обновления перезапустите воркеры очереди: работающий воркер держит старый код.

## [0.2.0] - 2026-11-15

### Добавлено

- **Отправка в мессенджер** для заявки, которая туда не уходила. Заявка, пришедшая до подключения MAX или Telegram, получила в карточке кнопку «Отправить в MAX» (или «Отправить в Telegram»). В JSON заявки новое поле `sendable`: мессенджеры, которые могут принять её сейчас (ещё не пробовали, подключены, включены и есть чат для формы). У мессенджера с ошибкой остаётся «Отправить ещё раз».

### Изменено

- «Состояние сайта» показывает модуль, который не подключён или выключен (Яндекс Вебмастер, Telegram, MAX, почта, IndexNow, аналитика, критический CSS, база знаний, файрвол MCP), жёлтой меткой «Не подключено», а не зелёной «Работает». Новый статус `HealthResult::off()` не меняет общий статус и код выхода `itk:doctor --ci`. Статус `off` теперь может прийти в `checks[].status` API админки `health` и в строках `itk:doctor`.
- В матрице прав роли столбец «Публиковать» стоит первым.

### Исправлено

- «Настройки → Уведомления» больше не отказывается сохранять пустой чат для остальных форм, когда подключён Telegram или MAX. Таблица показывает жёлтую подсказку, что заявки форм без чата не придут в мессенджер. `SettingsService::save()` тоже принимает такие маршруты.

### Удалено

- `Content\SettingsService::routesError()`, который проверял, что у подключённого мессенджера есть чат для остальных форм. Конструктор `SettingsService` больше не принимает аргументы `max` и `telegram`. Подробности в заметках к 0.2.0 в [UPGRADE.ru.md](UPGRADE.ru.md).

## [0.1.0] - 2026-11-15

Первый публичный релиз.

### Требования

- PHP 8.3 или новее и Symfony 7.4, либо PHP 8.4 или новее и Symfony 8.
- PostgreSQL 16 или новее с расширением pgvector версии 0.8 или новее. MySQL не поддерживается.
- Node нужен только для сборки админки из исходников и для критического CSS.

### Страницы и секции

- Страницы из секций, шаблоны страниц, правила размещения в дереве страниц и правило одного H1.
- Черновики с автосохранением, предпросмотр в шаблонах сайта, публикация и снятие с публикации.
- Оптимистичная блокировка черновиков: если черновик успел сохранить кто-то другой, сервер отвечает 409, и админка предлагает выбрать версию.
- ETag и ответы 304 для опубликованных страниц, заголовки безопасности на публичных маршрутах.

### Коллекции

- Коллекции, описанные в схеме или в классах-ресурсах, с полями, фильтрами, сортировкой, поиском и метриками.
- Виды списка: таблица, карточки, календарь, доска и дерево с перетаскиванием.
- Действия над строкой, выделением, списком и формой записи, с подтверждением и окном ввода.
- Повторяемые поля с заголовком и подзаголовком строки и дублированием. Поля в половину ширины и разделы формы.
- Twig-функции `itk_pages`, `itk_page`, `itk_collection` и `Content\ContentReader` для чтения содержимого в шаблонах.

### Меню и настройки

- Меню с областями и глубиной вложенности из схемы.
- Группы настроек из схемы, встроенные группы «Сайт» и «Аналитика и вебмастера» и настройки в коде.
- Оформление админки: цвета бренда и акцента и скругления.

### Медиатека

- Медиатека с папками, кадрированием и точкой фокуса.
- Копии в WebP и AVIF при загрузке и уменьшенные копии по запросу.

### SEO

- Правила SEO для любого адреса, переадресации и `sitemap.xml`.
- `/robots.txt` и `/llms.txt` отдаёт бандл, текст правится в **Настройки → SEO**. Файл в `public/` важнее.
- Разметка schema.org в JSON-LD на живых страницах: `WebSite`, `Organization` или `LocalBusiness`, `BreadcrumbList` и `BlogPosting`. Поля компании в настройках сайта. Событие `Event\SchemaOrgGraph` добавляет свои типы.
- Строка «ИИ-поиск» на экране «Состояние сайта» и в `itk:doctor`. Она предупреждает, если `robots.txt` закрывает ботов ИИ.

### Аналитика и вебмастера

- Яндекс Метрика (с Вебвизором), Google Analytics 4 и метатеги подтверждения Яндекса и Google. Бандл ставит их на живые страницы по настройкам. Счётчик, который уже есть в макете, не добавляется второй раз.
- Яндекс Вебмастер: подключение одним OAuth-токеном. Бандл добавляет и подтверждает сайт, отправляет `sitemap.xml` и показывает данные индексации в админке.
- IndexNow: если переключатель включён, воркер очереди сообщает Яндексу и Bing об опубликованных, перенесённых и снятых страницах.

### Заявки

- Заявки из форм со скрытым полем-ловушкой и ограничением частоты, статусами, видом «Доска» и повторной отправкой.
- Уведомления на почту, в Telegram и в MAX. Telegram и MAX необязательны, у каждого свой статус доставки.
- Токены ботов Telegram и MAX можно задать в **Настройки → Боты**. Они хранятся зашифрованными и применяются без перезапуска.

### Пользователи и доступ

- Пользователи и роли с правами по разделам, действиям и шаблонам страниц.
- Двухэтапный вход, восстановление пароля по почте и ограничение попыток входа.
- Команды `itk:user:password` и `itk:user:reset-2fa`.

### История и корзина

- История изменений страниц, записей, настроек и меню со сравнением и возвратом версии.
- Корзина для удалённых страниц и записей.
- Уведомления в админке.

### Производительность

- Кэш живых страниц. Публикация и другие изменения содержимого видны сразу. Им управляют Twig-функция `itk_cache()`, заголовок `X-ITK-Cache` и команда `itk:cache:clear`.
- Необязательный критический CSS: после публикации воркер вырезает правила первого экрана с помощью `crittr`, а `{{ itk_stylesheets() }}` встраивает их в страницу. Нужен Node 22 или новее.

### ИИ

- База знаний на pgvector: смысловой поисковый индекс опубликованного текста сайта, который воркер очереди держит в актуальном виде. Эмбеддинги строит OpenAI. По умолчанию выключена.
- MCP-сервер для ИИ-ассистентов по HTTP (`/mcp`) и stdio (`itk:mcp`) с API-ключами, областями доступа и аннотациями инструментов. Сайт может добавить свои инструменты.

### Эксплуатация

- Экран «Состояние сайта» в админке и команда `itk:doctor`. Они проверяют PHP, базу данных и pgvector, `APP_SECRET`, загрузки, очередь, Telegram и MAX, аналитику, IndexNow, Яндекс Вебмастер, ИИ-поиск, критический CSS и базу знаний.
- `GET /healthz` для мониторинга доступности.
- `itk:install` создаёт роли, настройки по умолчанию, таблицы очереди, главную страницу и первого администратора. Команду можно запускать повторно.

### Админка

- Админка на Vue 3, которая поставляется собранной вместе с бандлом.
- Интерфейс на английском, русском и казахском. Каждый пользователь выбирает язык в **Мой профиль**. Язык по умолчанию задаёт `itk_cms.admin_locale`.
- Адрес админки настраивается (`itk_cms.admin_path`).
- Контракт плагинов (`window.ITK`) для своих полей, экранов, действий, виджетов и кнопок редактора, с объявлениями TypeScript.

### Инструменты разработчика

- Генераторы `itk:make:*` для шаблонов, секций, коллекций (в том числе из описания или таблицы базы), полей, настроек и плагинов админки.
- `itk:schema:lint` и строгий режим шаблонов (`itk_cms.strict`).
- Комплект Docker в `docker/`: PHP-FPM, nginx, воркер очереди, PostgreSQL 17 с pgvector и Mailpit, стадии для разработки и продакшена.
- Правила для ИИ-агента, который делает сайт на бандле (`SITE-AGENTS.md`).
